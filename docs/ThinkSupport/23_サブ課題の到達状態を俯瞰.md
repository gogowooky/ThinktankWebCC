# サブ課題の到達状態を俯瞰

実装日：2026-09-17。

## 選んだ段階

22で追加した子BundleとP4の本人確認履歴を接続する。新しい管理入力を増やさず、親のOverview > 分析で、どこまで判断・実行できたかと残課題を確認できるようにした。

## 実装

- `SubtaskList` に、直接のサブ課題の検討・意思決定・実行・検証の到達状態を表示する。各段階の到達・再検討・対象外・未記録を個別に数える。対象外を到達に換算しない。
- `thinkProgress` の検証済み履歴の末尾を採用する。古い到達履歴より新しい再検討を優先する。旧ChatタイトルやAI提案からは推定しない。
- 保留件数、各課題の再開条件・残課題を表示する。確認日時・根拠・再開メモ・再確認日は折りたたんで参照できる。
- 記録なしと、未知の版・不正な記録を区別する。読めない記録は集計対象外の件数として明示し、他の課題の表示を継続する。
- 既存のP4保存後のVault通知で表示を更新する。親子の移動は22の導線を維持する。

## 保存と範囲

読み取り専用で、保存形式の追加・親の書き換え・完了の自動確定はない。読み込み済みVaultの直接の子だけを対象とし、孫の再帰集計や別端末の最新状態の自動取得は行わない。この範囲を画面にも表示する。

既存のパネル幅に関するステージ済み変更、幅調整フックとテストの削除、copyright.txtの変更は保持した。

## 検証

関連4ファイル・18テスト成功。最新確認の優先、段階の独立、対象外・保留・未記録・未知形式の扱い、保存通知後の表示更新、Vault切替、親記録の保全を確認した。フロント・サーバーの型検査、変更4ファイルのESLint、差分の空白検査、本番ビルドも成功。

本番ビルドはサンドボックスの親ディレクトリ参照制限で一度失敗し、権限を広げて再実行した。動的・静的importの混在とチャンクサイズに関する警告は残る。

実Gemini・BigQuery・ブラウザ画面での通し操作は未検証。

## 次の段階

サブ課題専用Chatの作成とWorkoutへの引継ぎを接続する。元の相談Chatを保全し、作成失敗からの再試行と重複防止を整える。その後、AIが会話から到達状態の候補を整理し、本人が重要な判断を確認する流れへつなぐ。複数の分解案、担当変更、親AIへの子課題状況供給、見直しと終了は残る。
