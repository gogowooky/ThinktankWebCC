# 次の行動からサブ課題を追加

## 操作と範囲

Bundleを参照したAIChatの直近の保存済み回答に `nextAction` 提案があると「次の行動をサブ課題にする」を表示する。本人が内容と課題名を確認して追加する。提案全体を1件のサブ課題として扱い、箇条書きを自動分割しない。課題名は200文字以内で編集できる。

サブ課題は独立したBundleで、提案本文を目的として保存する。完了条件は未記録として後から整理する。担当はWorkoutを初期値とする。親のOverview > 分析にはサブ課題一覧を表示し、子BundleをOverviewで開ける。子の分析には親課題へ戻る操作を表示する。

## 保存

子Bundleメタデータの `taskRelation` に `schemaVersion: 1`、`parentId`、元会話の `chatId` と `turnId`、`panel: Workout` を保存する。目的は既存P2形式 `thinkSupport` に保存する。子Bundle本文には元Chatの参照を保存し、会話本文を複製しない。親Bundleを別途書き換えず、Vault一覧にある子の親IDから一覧を構成する。

作成前に保存済み会話を再取得し、最新回答と一致することを確認する。別Vault、存在しない親・Chat、Chat単独対話からの追加は拒否する。同じ親・Chat・回答からの作成は、同時操作をまとめ、保存済み関係がVault内にあれば再利用する。失敗した保存は既存のメモリ上のロールバックを利用する。別端末との同時作成や、通信断で結果不明のままVaultを再読込せず再試行するケースの完全な冪等性は未対応。

## 未完了の範囲

計画のサブ課題段階の最初の部分であり、複数サブ課題の構造化された分解案、担当変更、専用Chatの作成、Workoutへの自動引継ぎ、完了状態の集計、親AIへの子課題状況の自動供給は未実装。元Chatの担当タイトルは変更しないため、既存のパネル別Chat絞り込みはそのまま適用される。親子関係だけで親Bundleの参照資料を自動拡張しない。
