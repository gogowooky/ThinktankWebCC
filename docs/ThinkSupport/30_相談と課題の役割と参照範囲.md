# 相談と課題の役割・参照範囲

## 合意した役割

Thinktankは相談を受け止め、会話で取り組む対象を整理する入口。新しい相談・再開はChat一覧で行う。AIChatの明示的なアクションは「相談を課題として開始」「相談に類似した課題を調査」とする。課題化後は開始操作を既存課題を開く操作に替える。資料追加はOverviewの役割で、ThinktankのThink一覧からOverviewへの既存D&Dを利用する。

見直し・分解・再開要約の必要性はAIが状況から判断して提案する。Thinktankには定型質問を入力する操作を置かない。他パネルの既存操作は維持する。本人の意思決定・完了・保留等は具体的な候補を本人が確認して保存する。

## 用語・タイトル

- Think：保存する記録の総称。Chat、Bundle、メモ等を含む。
- 相談：Chatで行う対話。課題化は必須ではない。
- 課題：取り組む対象として開始し、Bundleで管理するもの。一般の資料集Bundleと区別する。
- 新しい相談は `ASK:Thinktank｜タイトル`。
- 課題に対応するChatは `TASK:パネル名｜タイトル`。課題化してもパネル名は維持する。状態があれば従来の `[進行中]` 等を保持する。
- タイトルは表示用。TASKに手動変更してもBundle作成・関連付けは行わない。
- TODO／PROJ／EVNT／LOOPは旧タグとして解析・絞り込みを維持し、一括書換えしない。旧タグのChatを明示的に課題化した場合はtaskContext.previousKindに元タグを保存する。単発・繰り返し等の種類の自動移行は今回行わない。

## 課題化と保存

既存の課題名・目的・完了条件の確認を維持する。元のChatの題名を保存し、Chatを含む課題Bundleを作成する。Bundleメタデータの `taskOrigin: { schemaVersion: 1, chatId }` に元Chatを記録する。その後Chatの `taskContext: { schemaVersion: 1, bundleId }` とTASKタイトルを一回の保存で確定する。会話本文と他のメタデータは保持する。

同じChatへの同時作成は一つにまとめる。Bundle保存後にChat更新が失敗した場合は、Bundleの元Chat情報から再利用する。既存の対応Bundleがあれば新規作成しない。編集競合を上書きしない。Bundle保存の応答そのものが失われた場合の、複数端末をまたぐ完全な冪等性は未対応。

## AIChatの参照先

Overviewの表示Bundleを参照先に流用しない。Chatに保存された課題IDを基準とする。

1. ChatのtaskContext、既存subtaskChat、旧thoughtSupport.bundleIdを確認する。異なるIDがあれば競合として停止する。
2. 明示IDがなければBundleのtaskOriginを確認する。
3. 旧データはBundleの直接参照IDから一意な候補を確認する。タイトル一致は利用しない。RelatedIDsおよび読み込み済み本文のIDが対象で、検索条件だけによる包含は所有関係と見なさない。
4. 複数候補なら本人に対象を提示し、選択後に明示IDを保存する。
5. 明示IDの課題が見つからない場合、TASKだが課題が不明な場合は送信せず案内する。別のBundleへ自動で切り替えない。
6. 対応BundleのないThinktank相談はChat単独で利用する。

会話履歴の保存版を同期してからBundleコンテキストを取得する。同時実行すると自身のChat同期でVault更新検出が発生するため。変更のない保存版の反映ではVault更新通知を出さない。

## 類似課題の調査

クリックで保存済み相談を読み取り、読み込み済みVaultの課題名・目的・完了条件を照合する。相談の題名と直近12件の本人発言を用いる。AIの発言を本人の検索意図として利用しない。

現段階は日本語・英数字の共通語による検索。AIによる意味的な類似判定や全資料本文の検索ではない。結果には調査件数、共通語、目的、完了条件を表示し、最大10件を示す。現在対応している課題は除外する。候補なし・入力不足・通信失敗を区別する。

候補の「この課題をOverviewで開く」は閲覧だけで、相談の対応Bundleを変更しない。新規相談を検索結果の課題へ追加する専用の採用操作は今回追加していない。調査中に相談を切り替えた場合は中断し、古い結果を表示しない。

## 確認項目

- ASKの課題化後にTASKとなり、元会話・パネル・状態を保持する。
- Overviewを別課題へ切り替えてもChatの参照先は変わらない。
- 未課題化Chatが無関係なOverviewの資料を使わない。
- 旧ChatのID参照、複数候補、削除済みの対応課題を区別する。
- Chat関連付け保存の失敗・再試行・同時作成でBundleを重複作成しない。
- 類似課題の調査はクリックで実行し、候補を開いても相談の関連付けは変わらない。

サーバーのAI指示も変更しているため、利用時は開発サーバーを再起動する。

## 検証結果

全72ファイル・532テスト成功。その後の旧タグ保持の追加も関連11テストで確認。フロント・サーバーの型検査、変更ファイルのLint、サーバーとフロントのビルド成功。LintはTTVaultの既存未使用変数警告が1件、Viteは既存のimport混在・チャンクサイズ警告がある。

実ブラウザでASK／TASKのフィルター、相談アクション、対応課題名と参照資料、類似課題の検索完了を確認した。新規課題作成・失敗再試行・参照先切替の回帰は自動テストで確認。実ストレージへの新規課題作成からAI応答までの通し操作は今回未実施。
