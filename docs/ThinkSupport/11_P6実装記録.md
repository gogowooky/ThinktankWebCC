# P6 第一段階：手動の外部資料連携

実装日・公式資料確認日：2026-09-14。

続き：[12 P6復元とFile Search接続確認](12_P6復元とFileSearch接続確認.md)。自動連携先はGemini File Searchに決まり、記録の取込と読み取り専用接続確認を追加した。本書はその前の第一段階の記録である。

## 今回の範囲

OverviewのBundle状況に「外部資料連携」を追加した。利用アカウントでのAPI可否は未検証のため、P6の代替経路であるMarkdown書き出しとNotebookLMリンク登録を実装した。自動同期アダプターの実装・実証は次段階であり、P6全体の完了ではない。

1. 「登録済み連携を取得」で保存版と履歴を読む。
2. アカウントを区別する識別名（例 `work`）と既存ノートブックURLを入力する。識別名は認証済みアカウントIDではなく、本人が一貫して管理する別名である。
3. 「書き出す資料を取得」でP1のBundle内Snapshotを固定する。資料本文、取得日時、未保存編集、欠落等の注意事項、前回準備記録との差分を表示する。
4. 対応表JSONと、必要な資料ごとのMarkdownをダウンロードし、NotebookLMへの追加は本人が行う。本文はP1がハッシュ化したUTF-8文字列そのもので、ヘッダー追加・改行変換・BOM付加をしない。
5. 確認チェック後、「連携先と準備記録を保存」でBQへ記録する。ダウンロードの完了、外部アップロードの成功、外部同期の完了を主張しない。

リンク保存だけの利用も可能。`notebooklm.google.com/notebook/…` のHTTPS URLを対象とし、クエリ・フラグメントを除去して保存する。他のホストやEnterprise専用URLは今回のリンク登録対象外。資料書き出し自体は連携先なしでも利用できる。

## 保存・対応・失敗時の扱い

- Bundleの`Metadata.thinkExternal`にschemaVersion 1の追記履歴を保存する。既存本文、旧メタデータ、P2〜P5の記録を維持する。`saveThinkSupport`の既存の版条件付き更新を使う。
- `vaultId + bundleId + provider(notebooklm-manual) + accountKey`単位で最新のNotebook URLを解釈する。タイトルには依存しない。登録先変更でも旧履歴は残る。外部Notebookを作成しないため、この処理による外部の二重作成はない。別名の重複入力や外部での重複は検出できない。
- ManifestはSnapshot ID、取得日時、品質・警告と、各Think ID・ファイル名・本文SHA-256・観測更新日時・未保存編集の有無を持つ。本文はBQの連携履歴に複製しない。ブラウザの作業中メモリとダウンロードファイルに保持する。
- 状態は常に`prepared`。`recordedAt`は内部履歴の保存日時、`capturedAt`は資料取得日時であり、`lastSyncedAt`として解釈しない。外部Source ID、外部版、最終成功ハッシュは未取得。外部引用からの自動復元や同期状態の検証はできない。
- 同じ登録先の前回準備記録に対し、Think IDと本文ハッシュで追加・変更・変更なしを比較する。今回取得できない資料は範囲変更や読込失敗も含み、削除の根拠にしない。登録先が変われば差分の基準を引き継がない。
- 操作IDで通信応答喪失後の再試行を冪等化。同じ操作IDの異なる入力、古い保存版、原子的更新の競合は409。再取得は入力を保持して確認を解除する。履歴は100件／2MB上限で停止し、自動削除しない。履歴JSONの書き出しが可能。
- リンク登録APIは既存の認証済み`/api`境界内に追加。外部URLをサーバーから取得しない。認証情報用のフィールドは設けず、未知の入力フィールドは拒否する。BQ保存は既存同様PWA方式のみ。他方式では資料ダウンロードが利用可能。
- UI下書きはVaultオブジェクトとBundle単位で分離し、切替後の遅延応答を元の下書きへ戻す。未保存編集・処理中はページ離脱時の確認対象となる。ブラウザを閉じると下書きと資料本文は消える。
