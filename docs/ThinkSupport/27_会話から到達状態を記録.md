# 会話から到達状態を記録

実装日：2026-09-22。

## 今回の段階

25の次段階として、Bundleを参照する会話の本人の報告から、検討・意思決定・実行・検証の到達状態候補を整理し、本人確認後に既存P4履歴へ記録する導線を追加した。Workout専用Chatを含む共通AIChatが対象。

## 候補と確認

AI応答に省略可能な `progressProposals` を追加した。旧履歴は変更せず読める。新しいProviderの応答スキーマでは配列を必須とし、候補がなければ空配列とする。各候補は段階、到達／再検討／対象外、今回の本人の発言の原文引用、整理理由から成る。

サーバーと保存履歴の読取時に、段階・値・重複・件数・引用の一致を検査する。Chat単独対話では候補を許可しない。本人の希望・予定・質問を完了報告として扱わず、一つの到達から他段階の到達を推定しないようProviderへ指示する。原文一致は意味の正しさの保証ではないため、候補は必ず未確認として扱う。

直近の保存済み回答に「到達状態の候補を確認」を表示する。操作後に保存先から最新の到達状態、目的、完了条件を取得し、各候補の変更前後、本人の発言、AIの整理理由を表示する。確認根拠と残課題は編集できる。未記録の残課題を自動で「なし」にせず、入力がなければ保存できない。「本人の判断として確認して記録」でのみ保存する。候補が誤っていればキャンセルし、会話で訂正できる。

提案対象以外の段階、保留、再開条件・要約、再確認日は最新記録から引き継ぐ。以前の根拠資料を今回の会話報告の根拠へ転用せず、新しい確認根拠には会話ID・日時・本人の引用を記載する。以前の根拠は既存履歴に残る。AI候補はChat本文にも未確認と明記して同期する。

## 保存と復帰

既存ProgressServiceと保存版検査を利用し、本人確認の履歴を追記する。保存成功後にVaultの `thinkProgress` を更新するので、親課題の既存サブ課題一覧にも反映される。親課題自体の到達状態は変更しない。

会話IDを操作IDとして使う。同じ入力による再試行は既存のサーバー側冪等処理で二重追加を防ぐ。画面を開き直した場合も、候補確認時に同じ操作IDを検出して記録済みと表示する。保存失敗時は入力を画面に保持し、保存競合時には最新記録を再取得して比較・確認する。再取得でも編集した根拠・残課題は保持する。自動再送信・自動保存は行わない。
