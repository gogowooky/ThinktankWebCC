# サブ課題の専用ChatとWorkout引継ぎ

実装日：2026-09-17。

## 選んだ段階

24の会話開始の変更を保持し、22・23のサブ課題からWorkoutで個別に相談する段階を接続した。ユーザーが追加の管理項目を入力せず、採用済みのサブ課題の目的・参照資料を使って会話を続けるための導線である。

## Step 1：専用Chatを保存・再利用する

サブ課題の分析と親のサブ課題一覧に「Workoutで相談する」を追加。押した時点で `ASK:Workout｜課題名` のChatを作る。Chatメタデータの `subtaskChat: { schemaVersion: 1, bundleId }` を本文と同じ保存操作に含める。既存のCreateBlankThinkへ初期メタデータの省略可能な引数を追加し、従来の呼び出しを維持した。

同じVaultの同じサブ課題について作成中の処理を共有する。読み込み済みのChatに所属があれば再利用し、複数見つかった場合は自動選択せずエラーを表示する。元Chatの本文・担当・履歴を変更せず、架空の質問やAI回答を生成しない。

## Step 2：子Bundleへ参照を追加する

Chat保存後に子Bundleへ `* Chat ID` 行を追記する。既存の本文・コメント・未知の記述を再構成せず保全し、既存メタデータも保持する。参照済みなら再保存しない。未保存の編集や本文未取得がある場合は停止し、編集保存・再読込を案内する。

既存の保存版を付けて競合検査を行う。関連付けだけ失敗した場合、Chatの所属は保存済みなので同じChatを再利用して再試行する。保存中のローカル編集も上書きせず、再読込を案内する。Chat作成自体が失敗した場合は既存のメモリ上のロールバックを利用する。

## Step 3：Workoutへ引き継ぐ

関連付け成功後に、Overviewを子Bundleへ切り替え、Workoutの設定領域を開いてAIChatを選択する。選択IDの保存と既存の選択イベントを使うため、閉じていた領域でも専用Chatを選択できる。AIには従来のBundleコンテキストを通して子課題の目的・資料が渡る。重要な決定・完了は既存の確認操作を経る。

準備中に別課題・Vaultへ移動した場合は遅れて完了した処理で画面を切り替えない。保存済みChatは作成元に残る。ボタンのエラー表示から同じ操作を再試行できる。

## 検証

関連6ファイル・21テスト成功。Chat所属の同時保存、並行作成の共有、再読込後の再利用、関連付けだけの再試行、本文の保全、保存中の編集保護、遅延した画面移動の抑止、Workoutの表示・選択を確認した。フロント・サーバーの型検査と差分の空白検査も成功。変更対象のLintはエラー0件、TTVaultの既存未使用import警告1件。

本番ビルドも成功。動的・静的importの混在とチャンクサイズに関する警告は残る。実Gemini・BigQuery・実ブラウザでの通し操作は未検証。

## 制約と次の段階

読み込み済みVaultの所属情報を使った再利用であり、別端末との同時作成や保存結果不明の通信断について完全な冪等性は保証しない。再試行前にVaultの再読込が必要な場合がある。Chatの所属を変更するUI、担当変更、一般のOverview・Workout・ReThinkの新規チャット行は今回の対象外。

次は会話から到達状態の候補を整理し、本人確認後に記録する段階。親AIへの子課題状況供給、複数分解案、見直しと終了は引き続き残る。今回、親Bundleの内容・到達状態・参照範囲は変更しない。
