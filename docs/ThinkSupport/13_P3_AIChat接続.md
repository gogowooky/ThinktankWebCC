# P3 続き：AIChatへの資料付き対話の接続

実装日：2026-09-14。

## 背景と今回の範囲

新しい引用付き対話はOverviewのBundle状況に実装済みだったが、各AIChatは旧履歴の閲覧専用で入力欄がなかった。日常の相談入口を整えるため、P6の資料同期へ進む前にP3の画面接続を追加した。

Thinktank・Overview・Workout・ReThinkのAIChat、およびWorkoutのChatペインが共用するSupportChatに、「資料に基づく対話」「旧会話の履歴」の切替を追加した。旧会話が選択されている場合は従来の履歴を初期表示し、選択されていない場合は新しい対話の入口を表示する。

## 利用手順

1. AIChat上部で「資料に基づく対話」を選ぶ。
2. 「相談するBundle」を選ぶ。表示中／旧会話に関連するBundleがある場合はボタンで選択できる。候補の存在だけで資料を読み込んだり送信したりしない。
3. BigQueryモードでは「今回の質問」の入力欄が表示される。「資料・履歴・接続状態を確認」で送信範囲とサーバー設定を確認する。
4. 資料と質問を確認し、送信確認チェック後に送信する。生成中断、保存だけの再試行、未保存回答のJSON書き出しは既存P3と共通。
5. 引用の出典ボタンでWorkoutに原本を開く。既存ペインがあればそこへ移動し、なければ追加する。

AIが停止中でもBigQueryモードの質問欄には入力できる。送信にはP3のAI設定が必要。Gemini File Searchの接続設定だけでは対話AIは有効にならない。今回、AIの有効化や認証設定の変更、実APIへの質問送信は行っていない。

## データと切替

- 保存先は選択したBundleの既存`thinkConversations`。旧Chat本文や管理メタデータへ追記しない。旧会話は明示的な切替で閲覧でき、旧AI処理は再開しない。
- Bundleは明示選択する。周囲のOverview Bundleが変わっても相談対象は維持する。Vaultが変わると選択を解除する。選択したBundleが一覧から消えた場合は対話を表示せず再選択を求める。
- 質問下書き・未保存回答はVaultオブジェクト、Bundle、画面の識別子ごとに分離する。Overviewと各パネルが同じBundleを開いても下書きを上書きしない。対話履歴そのものは同じBundle・Vaultで共有する。
- 履歴表示への切替やBundle変更時にはP3の生成中断処理が働く。戻った際は対象Bundleを選び直すことで、同じ画面の質問・未保存回答を再表示できる。参照資料と送信確認は再取得する。
- 未保存回答を保存する際は、同じ回答が既に別の再試行で処理された場合に新しい下書きを消さないよう、保留中の回答IDを確認する。
- AI提案は未採用として表示し、採用先としてOverviewの手動編集を案内する。

## 検証

新規テストでは明示的なBundle選択、周囲のBundle変更に対する対象維持、旧履歴との切替、OverviewとAIChatの下書き分離を確認する。既存の停止中通信禁止、送信確認、中断、保存失敗時の再試行、旧本文・メタデータ保全テストも実行する。

型検査、変更したTypeScriptファイルのESLint、全体48ファイル・342テスト、フロントエンドビルドが成功した。既存の大きなチャンク警告と、TTApplicationの動的／静的import混在により別チャンクにはならない旨の警告がある。サーバーコードの変更はない。実AI・実BQ・実画面での受け入れは未実施。

## 次の段階

P6では指定済みのGemini File Searchを継続する。接続先の実証、Bundleとストアの永続対応、確認済みSnapshotの資料送信、成功分のハッシュ保存、部分失敗からの再開を実装する。File Searchによる検索回答と今回のP3対話の接続は、その引用対応を確認した上で進める。
