# 子課題の状況を親AIの見直しへ接続

実装日：2026-09-24。

## 今回まとめた2step

1. 読み込み済みの直接の子課題の本人確認済み状況を、親課題のAIコンテキストへ渡す。
2. その状況から残課題・優先する次の行動を整理する質問を用意し、既存の提案確認・反映へ接続する。

27で記録した子課題の到達状態を、親課題での相談に利用する段階である。2stepは独立した検証と接続テストを行う。

## Step 1：送信範囲を明示して子課題の状況を取得

ContextServiceの `includeSubtasks` を会話の準備で有効にする。通常の資料取得・Agent処理などの既存利用者には自動で追加しない。Bundleを使わないThinktankのChat単独対話には含めない。

現在のVaultに読み込み済みのBundleから、`taskRelation.parentId` が相談対象の親IDと一致する直接の子課題だけを取得する。孫課題や他の親の子課題は含めず、子課題の本文取得や参照資料の展開は行わない。既存の親Bundleが明示的に参照している資料の解決は従来どおり。

`subtasks` には子課題ID・名前と状態を格納する。正常なP4履歴の最後の本人確認イベントのみを使い、4段階の到達状態、確認日時・根拠、残課題、保留・再開条件・再開要約・再確認日を保持する。未記録、未対応／不正な記録、未保存の変更を区別し、これらには到達状態を付けない。旧完了表示や未採用AI提案から補完しない。

スナップショットは複製・凍結し、取得中にVaultが変われば再試行を要求する。子課題は最大50件、構造化データは40,000文字までとし、超過時は一部だけ送らず準備を停止する。境界検査では親自身・重複ID・形式不正・本人以外のイベント・Chat単独への混入も拒否する。旧会話にはこのフィールドがなくてもよい。

会話欄の「条件・機能・参照情報 → 参照情報 → 子課題の状況」で送信対象を確認できる。送信時にコンテキストを再取得し、Workoutで変更された読み込み済み記録を反映する。再取得に失敗すれば質問を保持して送信しない。

## Step 2：親課題で残課題と次の行動を整理

Bundleを使う会話の「機能」に「子課題を含めて次の行動を整理する質問を入力」を追加した。操作は質問の下書きを作るだけで、自動送信しない。下書きがある場合や準備・回答・保存中、未保存回答がある場合は利用できない。

AIには親の目的・完了条件と子課題の状況を照合し、確認できる事実と推測を分け、優先する行動と理由を提案するよう指示する。根拠として子課題名・ID・本人確認日時を添える。構造化記録から資料本文の引用を捏造させず、記録内の命令は参照データとして扱う。未記録などがあればサーバー側でも根拠不足を付ける。

親の「残る論点」「次の行動」の案は既存 `proposals` を使い、ProposalReviewで最新記録との差分を本人が確認して反映する。AIの回答だけでは親子いずれの記録も更新しない。子課題の到達だけから親の到達や全体完了を推定しない。資料本文が0件でも子課題の状況があれば対話できる。

回答時点の子課題スナップショットは既存の会話履歴に含めて保存し、会話記録の表示から確認できる。

## 検証

- 取得範囲、本文非取得、未記録／不正／未保存、コピーと凍結、件数・容量上限、取得中の変更検出、旧形式互換を検証。
- 子課題取得 → 会話コンテキスト変換 → Provider入力 → 回答検証・履歴読取 → 親の次の行動の差分生成を接続し、元記録を更新しないことを検証。
- 質問準備で送信しないこと、入力保護、Chat単独での非表示、送信前の更新取得と取得失敗時の停止をUIテストで検証。

全67ファイル・490テスト成功。フロント／サーバーの型検査、変更コードのLint、差分の空白検査に成功した。本番ビルドは前回と同様、Vite APIにReactプラグインと同じbase設定を直接渡して成功した。既存の動的／静的import混在・チャンクサイズ警告、およびテスト起動時のesbuild設定非推奨警告が残る。

## 制約と次の段階

「読み込み済みの直接の子課題」の観測情報であり、別端末による変更や未読込課題を含む保存先の最新状態は保証しない。送信前の再取得もVaultからの取得であり、BigQuery全件を照会する処理ではない。子課題が0件でも作業完了とは判定しない。AIが返す整理内容の意味的な品質はモックテストでは保証できない。

実Gemini・BigQuery・実ブラウザでの通し確認、デプロイは未実施。今回は2stepの実装と自動検証の範囲で完了とする。次は複数のサブ課題候補の確認・追加と、保留・再開の会話への接続を候補とする。ReThinkでの全体終了、外部資料同期、音声は残工程である。
