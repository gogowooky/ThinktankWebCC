## 1. 対象範囲と到達点

Bundleを正本とするAI-neutralな基盤の上に、共通コンテキスト、課題を俯瞰するOverview、資料に基づく対話、Agent処理、外部同期を段階的に追加する。

最初の利用可能な到達点は「AIなしで資料と進行情報を手動管理できる新Overview」。次の到達点を「引用付きのテキスト対話」とする。NotebookLM同期と音声が未提供でも、思考支援の基本機能が成立する順序で進める。

Bundleの名称・IDの変更、既存データの一括再分類、外部サービスの会話完全復元は対象に含めない。

成果物：保全対象一覧、復元手順・検証記録、現行UIの文言修正、手動確認記録。

受け入れ条件：Thinkの作成・編集・保存・再読込、Bundleの作成・解決、Overviewの表示、Workoutのペイン操作、会話履歴の閲覧を検証環境で確認。履歴閲覧で旧AI処理が再実行されない。

保全確認が未完了でもソース上の非破壊開発は進められるが、実データ移行と運用反映の前には完了させる。

### P1：読み取り専用ContextService

作業：`TTVault.GetThinksForBundleAsync`を利用するアダプターを設け、資料範囲、版、既存thoughtSupportの出典付き項目をSnapshotへまとめる。動的Bundle、入れ子、除外条件、本文未取得、競合する決定を扱う。資料解決の既存実装が欠落を完全に報告できるかも検証する。

成果物案：`src/services/ContextService.ts`、共通型、既存メタデータ読取アダプター、テスト。ここで既存データを書き換えない。

受け入れ条件：Bundle外資料の混入なし、欠落の黙殺なし、非破壊読取、同じSnapshotを複数画面・処理から参照可能。切替や遅延読込で別Bundleの結果を表示しない。

実装追記：元Vaultのコピーに既存Bundle解決処理を適用する方式を採用。空Bundleの暗黙的な全件展開、循環、競合する検索条件はコンテキスト側で抑止し、既存UIの既定動作は維持する。資料本文はSHA-256で識別する。検索APIの完全性と本文APIの版整合が確認できない場合は、Snapshotを`partial`として明示する。

## 5. 検証方針

| 対象 | 主な検証 |
|---|---|
| ContextService | 入れ子・動的条件・除外・欠落・競合・範囲固定 |
| 思考状態 | 保存と再読込、本人確認、旧メタデータ保全、同時編集 |
| Conversation | AI停止、引用整合、資料不足、切替競合、中断 |
| Agent | 部分失敗、重複防止、適用差分、基準版不一致 |
| 外部連携 | ID対応、更新判定、再関連付け、切断復帰、権限不足 |
| UI | 4パネル間の操作、狭い表示、Simpleモード、キーボード、停止・エラー表示 |

純粋な状態処理は単体テスト、サービス境界は統合テスト、操作の連続性はブラウザ／Electronの実機確認で検証する。外部APIは検証用資料・接続先で実証し、保存をモックしたテストと区別して記録する。

## 6. 変更の保全と戻し方

各段階を独立した変更単位としてコミットし、成果物と検証結果を記録する。旧コードは比較・互換確認に利用するが、旧ルートをそのまま本番のAI経路へ戻さない。

新規保存項目はスキーマ版を持たせ、移行時に元データを保全する。AIを停止しても、新たに作った手動記録と成果物は読める状態を維持する。外部同期を止める操作が、ローカルや外部の資料削除にならないようにする。
