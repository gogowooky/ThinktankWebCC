# 相談から目的と完了条件の引継ぎ

## 今回の実装

Thinktankで「この相談を課題として始める」を押すと、選択Chatの保存済み履歴を取得する。直近の回答がChat単独対話で、AI提案に目的と完了条件の両方がある場合、その内容を課題名とともに確認できる。「作成してOverviewで開く」で採用する。直したい場合はキャンセルして会話を続ける。

過去の別回答の提案を合成せず、別Vaultや別Chat、既存Bundleを参照した提案も新規課題へ転用しない。両項目が揃わない場合は従来どおり課題名とChatの関連付けだけを保存し、課題作成後の対話で整理できる。AIへ追加リクエストを自動送信する処理は追加していない。

## 保存と切替

目的・完了条件は既存P2形式のBundleメタデータ `thinkSupport` に保存する。Bundle本文のタイトル・Chat参照とメタデータを一回の保存で送信し、空Bundle作成後に課題概要を別保存する方式は使わない。会話本文はChatに残す。本文への課題概要ブロックの追加は今回の対象外。

作成前に保存済み会話の候補を再取得し、確認時から変わっていれば作成を止めて再確認する。二重クリックは処理中に抑止する。Chat・Vault切替時は確認画面を閉じ、遅れて到着した結果を反映しない。保存失敗時は既存のロールバック処理を使う。ただし通信断による保存結果不明時の再試行の完全な冪等性は未対応。

## 検証と残る作業

目的・完了条件の候補選択、確認前の保存抑止、会話更新時の再確認、Chat切替、Bundleと概要の一括保存、失敗時のメモリ上のロールバックをテストする。実際のGeminiとの対話からBigQueryへ保存する通し操作は未確認。

本実装は計画の課題化の一部分。AIが毎回両候補を揃える保証はなく、一問ずつの対話を含む通し検証が必要。サブ課題追加、個別解決、全体の見直し・終了の接続も引き続き未完了。

検証結果：関連テスト3ファイル・11件、フロントエンド／サーバーの型検査、本番ビルドに成功。変更対象のESLintはエラー0件（既存箇所の警告9件）。git diff --checkも成功。
