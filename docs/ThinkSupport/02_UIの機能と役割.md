# UIの機能・役割

作成日：2026-09-13。現状は`f69259c`の描画コードを確認したもの。画面を実機で操作して確認した記録ではない。

## 1. 画面全体

通常のレイアウトは左からThinktank、Overview、中央のWorkout、右のReThinkで構成される。下部には共通ステータス領域がある。各パネルは開閉でき、SimpleモードではOverviewとReThinkが非表示になる。Thinktankの会話タブもSimpleモードでは非表示になる。

| パネル | 現在の役割 | 思考支援で担わせたい役割（設計案） |
|---|---|---|
| Thinktank | Vault内のThinkを探し、整理する入口 | 取り組む対象と資料範囲を選ぶ |
| Overview | 選択Bundleの資料・状況・関係を俯瞰する | 目的、根拠、判断、次の行動を共有する中心 |
| Workout | 個々のThinkを開き、編集・比較・閲覧する | 考えを具体的な記録・成果物にする |
| ReThink | 担当する過去の会話を参照する | 問い直し、反証、振り返りを行う |

将来の役割は別々のAI人格を必須としない。同じ課題を異なる視点から扱うUIとして、共通コンテキストを使う。

## 2. Thinktank：資料と課題の入口

### 現状

- 「Think一覧」でタイトル、本文検索、作成・更新日、コンテンツ種別などを使って対象を絞る。
- 一覧のチェック、列表示、並べ替えを使って対象を整理し、Bundle作成やWorkoutでの表示につなげる。
- 「会話履歴」で担当する会話を選び、保存済みの内容を読む。
- 設定タブを持つ。BigQuery同期ボタンはコールバックが渡される場合に表示される。表示の存在は接続成功を意味しない。

### 設計案

「どの課題・資料を扱うか」を選ぶ入口とする。AIに全Vaultを常時渡す方式にはせず、選択したBundleと送信対象を確認できるようにする。Bundle未選択の対話で新しい課題を作る場合は、題名・目的・初期資料を提案として示す。

## 3. Overview：現在のBundleを理解する

### 現状

| 表示 | 機能 | 注意点 |
|---|---|---|
| Think一覧 | 選択Bundleに含まれるThinkを検索・絞り込みし、Workoutで開く | Bundle未選択時は選択を促す |
| 分析 | 管理対象の会話を状態ごとにまとめ、その他の記録とともに示す（この課題の状況） | 主に会話タイトルの管理状態を表示している |
| 会話履歴 | 会話一覧と共通の閲覧専用SupportChatを表示する | 新規のAI応答は生成しない |
| 設定 | Bundleのタイトル編集、ID・日付・種別・参照情報の表示 | 「Bundleをクリア」は選択解除の操作 |

「この課題の状況」の完了表示は、本人による実施・検証完了を保証しない。実装にもその区別を伝える注記がある。

### 設計案：Thinktank内のNotebookLM型UI

資料一覧、資料に基づく対話、引用、成果物を同じBundleの作業空間として扱う。Google NotebookLMそのものの画面埋め込みを前提にしない。

| 配置の案 | 常時見える内容 | 主な操作 |
|---|---|---|
| 上部の課題概要 | 目的、段階、暫定結論、決定、論点、次の行動、完了条件 | 編集、根拠の確認、変更提案の承認 |
| 資料領域 | 対象Think、参照版、読み込み状態 | 対象選択、引用元をWorkoutで開く |
| 対話領域 | 質問、回答、引用、回答範囲 | テキスト入力、将来の音声対話 |
| 処理・成果領域 | Agentの進捗、成果物、適用前の差分 | 中断、再試行、適用 |

狭い画面では資料・対話・成果をタブで切り替える案とする。課題概要は簡潔な表示へ縮約しても、現在の対象Bundleと次の行動は見失わないようにする。具体的な寸法・配置はプロトタイプで決める。

## 4. Workout：資料を読み、記録を作る

### 現状

複数ペインでThinkを開き、分割や表示形式を切り替える。TextEditor、Markdown、DataGrid、Card、Graph、Html、Chatの表示部品があり、左のタブには各表示形式とWorkout全体の設定入口がある。

表示・編集能力は形式ごとに異なる。Chat表示は現在閲覧専用である。ただし会話ThinkをTextEditorで開く編集経路は存在するため、「チャットデータ全体を編集禁止にした」とは扱わない。旧メタデータの会話と本文に差異がある場合、現行の読取処理は本文との整合性を確認する。

### 設計案

比較、下書き、成果物の編集、引用元の確認を担う。AIが作る成果物は対象Thinkと根拠を示し、本人が確認して反映する。ペインを切り替えただけで実行中Agentの対象資料が変わらないよう、処理開始時のSnapshotを固定する。

## 5. ReThink：振り返りと問い直し

### 現状

AIChatとChatファイル一覧が中心である。設定タブは「今後追加予定」の表示であり、完成した設定機能ではない。Chatファイル一覧はOverviewで選択中のBundleを対象に、Chatタイトルの担当がReThinkのファイルを表示する。Bundle外になった選択は解除する。

### 設計案

「別の見方はないか」「根拠が不足していないか」「実行後に何を学んだか」を扱う。Overviewと異なる独自の確定状態を持たず、同じBundleの判断を参照し、見直しを提案する。提案を採用した場合に共通の思考状態を更新する。

## 6. 会話履歴の共通仕様

現行のSupportChatは4パネルおよびWorkout内のChatMediaから使われる。

- 保存済み会話の読取とエラー時の読み込み再試行を行う。
- 目的、現在、旧AIの提案、決定、残る論点、次の行動、完了条件を表示する。
- 段階と暫定結論は「未記録」の固定表示であり、入力・推論機能はない。
- AI送信用入力欄、モデル選択、旧AI処理の適用操作は表示しない。パネルの会話保存ボタンは無効。
- 未反映の旧AI処理がある場合は存在を表示し、自動実行しない。
- 会話一覧ではTODO／PROJ／ASK／EVNT／LOOP／未分類、未着手／進行中／待機／保留／完了／中止／状態未設定のフィルターを備える。

この種類・状態は旧会話の管理体系であり、将来の検討完了・意思決定完了などとは別である。既存ラベルを無断で変換しない。

## 7. UIで残っている不整合と確認事項

現行`BundleStatusView`の空状態には、停止中の「AI相談」で新しく話すよう案内する文言が残っている。「この相談を続ける」というボタンも現在は閲覧専用の会話を開く。新UIに進む前に、会話履歴の状態に合う案内へ直す必要がある。本書作成ではコードを修正していない。

一部の要素IDやコードコメントには旧名称`AI`が残る。機能が有効であることを意味しない。表示名・操作説明・キーボード操作の整合確認を実機で行う。

また、履歴パネルの情報欄は選択会話の記録であり、Bundle全体の合意を集約した状態ではない。新Overviewでは出典と集約規則を持つContextServiceへ接続する。

## 8. 利用の流れ

現状で可能な流れは「Thinktankで資料を探す → BundleをOverviewで開く → 状況や関係を確認する → Workoutで読む・編集する → 過去の会話を参照する」である。

将来はこの流れに「資料範囲を固定して質問する → 引用を確認する → 判断を記録する → Agentの成果を確認する → 実施・検証結果を記録する」を追加する。
