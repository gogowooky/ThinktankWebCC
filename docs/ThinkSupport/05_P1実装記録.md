## Snapshotの内容

- 識別・時刻：schemaVersion、snapshotId、vaultId、bundleId、startedAt、capturedAt。
- 根拠：ルートBundleと読込済みの入れ子Bundle定義、解決済みThink ID、読込成功した資料本文。
- 資料：Think ID、タイトル、種別、SHA-256ハッシュ、正規化方式`exact-utf8-v1`、開始時に観測したUpdatedAt、本文の取得元、未保存変更の有無。
- 思考状態：goal、current、decisions、openQuestions、nextAction、completionCriteria、legacyProposalsを出典ごとに保持。
- 未実装の意味付け：stageとprovisionalConclusionは空配列とし、旧currentやproposalsから推定しない。
- 診断：qualityとissues。返却オブジェクトは深くfreezeし、元データと参照を共有しない。

旧confirmedAtとconfirmationQuoteは「旧レコード全体の確認記録」として渡す。各項目の本人確認を保証するものではない。複数の異なる決定文字列を競合候補として報告するが、意味的な矛盾検出や採用判断はしない。

## 範囲と失敗時の挙動

| 条件 | P1の挙動 |
|---|---|
| Vault一覧が未読込／対象がBundleでない | 明示的なエラーで停止 |
| ルートBundle本文が取得不能 | 資料解決を行わずエラー |
| 空Bundle・除外指定のみで全件へ拡張されるケース | 全件展開を停止し、空資料＋診断 |
| 循環または競合する検索条件 | 資料範囲を確定せず、空資料＋診断 |
| 明示IDや検索結果IDがVault一覧にない | missing_thinkを報告。別の資料で補わない |
| 明示的な除外対象 | 結果から除外。欠落扱いにしない |
| 本文がnull／通信失敗 | load_failedを報告し、本文を架空の空文字として登録しない |
| 正常な空本文 | タイトルを含む資料として保持 |
| 本文やBundleが途中で編集される | context_changedで停止し、再試行を求める |
| Bundleの切替・中断 | 旧要求は返さずAbortError |

既存UI向けのGetThinksForBundleAsyncの既定値は変えていない。新しい保守的な範囲制御はP1の呼出しだけに適用する。thoughtSupport.referencesをたどってBundle外資料を自動取得しない。

## 現行APIによる制約

1. BQ検索は現行実装で最大200件、ストレージのsearch契約は完全性や次ページを返さない。既定アダプターでは検索を利用した場合に必ずsearch_incompleteを報告する。結果件数が少なくても完全とは断言しない。検索方式とAPIの改善は別の変更として扱う。
2. getContentは本文のみを返し、その版や対応するメタデータを返さない。リモート本文を取得した資料にはremote_version_unverifiedを付ける。本文ハッシュは実際に受け取った本文を識別するが、BQ上の一時点のトランザクションスナップショットではない。
3. quality=completeは、捕捉したクライアント状態の解決で既知の診断がないという意味。BQの最新状態や資料内容の真実性を保証しない。既知の診断があればpartialとする。
4. dirtyなThinkは開始時のメモリ上の内容を使用し、hasUnsavedChangesを付ける。勝手に保存・再取得しない。
5. Snapshotはメモリ上で返す。永続化、引用位置抽出、保存期間、Bundle全体の新しい状態管理はP2以降。
6. 読取中の元Vault変更を検知するため、開始時と終了時のクライアント状態を比較する。無関係なThink更新でも再試行になる。大量データ時のコピー・ハッシュ・比較コストは実データ相当の検証で今後計測する。
7. 中断は結果の採用を停止する。既存ストレージAPIはAbortSignalを受けないため、開始済みのHTTP要求自体が中止されるとは限らない。
