# Chat本文とAIChat履歴の統合（2026-09-16）

## 利用者に見える動作

ChatはThinkファイルの一種であり、TextEditorはChat本文の全テキストを表示する。ThinktankのAIChatとWorkoutのChatペインは、選択した同じChat IDの会話を表示し、そのChatへ質問と回答を保存する。ThinktankではOverviewのBundleを選択しなくてもChat単独で対話できる。Bundleが選択されている場合は、その資料を参照する。挨拶など資料上の事実を述べない応答には引用を要求しない。

通常の会話欄は発言と必要な出典を中心に表示する。Snapshot詳細は「参照情報・その他」の「会話記録の確認」に置く（保存済み会話のJSON書き出しは2026-09-19に廃止。[26 会話開始の資料範囲と入力操作](26_会話開始の資料範囲と入力操作.md) を参照）。送信操作が送信の意思確認を兼ね、別の確認チェックは求めない。

## 保存と旧形式の復元

- 新しいAIChatの構造化記録は、選択Chatのメタデータ `thinkConversations` に置く。同じ質問・回答・出典・提案をChat本文の `thinktank-ai-conversation:start/end` で囲んだ管理区画へ同期する。既存の手書き本文は残す。本文とメタデータはBigQueryの同じ版条件付き更新で保存し、Bundleの本文や会話履歴へは保存しない。
- 旧Chat本文の `## 質問` とそれに続く回答は、読込時に `legacy-text` の会話として復元する。すでに構造化記録にあるIDを重複追加しない。復元分と新形式分を同じ `thinkConversations` へ永続化し、表示を切り替えても件数が戻らないようにする。
- AIChatの初期表示はVaultにあるChatメタデータの履歴を使い、サーバーから最新履歴を再取得する。再取得後に本文とメタデータを更新し、開いているWorkout表示にも通知する。次のAI応答には、この統合履歴の直近6往復を渡す。
- 保存失敗時には回答と質問を保持し、同じ回答IDで保存だけ再試行できる。再送信してAIを二重実行しない。

## 実データでの照合

Chat ID `2026-09-09-141300` は、旧本文から復元した12件とGeminiの新会話1件を合わせて13件となった。統合処理後にサーバーから二度読み直し、両回とも13件を取得した。これによりTextEditorとAIChatが同じChatファイルを参照することを確認した。ただし、各画面のスクロール位置と表示形式は異なるため、同じ発言が同じ画面位置に現れるわけではない。

この実データ照合は対象Chatの履歴件数と保存先の確認であり、全Chatの旧本文が完全に自動解釈できることまでは保証しない。旧本文に `## ` を別用途で使った場合は、会話として復元され得る。
