# Thinktank アプリケーション仕様書：03. データモデル・ファイルフォーマット仕様

本ドキュメントは、アプリケーションで扱うオブジェクト指向データモデル、および永続ストレージに保存される際のテキストファイルフォーマット仕様とパース・シリアライズアルゴリズムについて定義します。

---

## 1. データ階層モデル

データは、以下の親子関係を持つクラス構造でメモリ上に配置されます。

```
TTVault (クラス: TTVault)
  └── Thoughts (クラス: TTThink[])  ※ContentType='thought' のデータ一覧
        └── Thought (クラス: TTThink) ※特定のテーマ
              └── Think (クラス: TTThink) ※個別データアイテム
```

> [!NOTE]
> * `TTVault` は `TTThink` のコレクションを保持します。
> * `Thoughts` は、`TTVault` 内の `ContentType` が `'thought'` である `TTThink` の集合（配列）を指します。
> * `Thought` は特定のテーマ（親となる `TTThink`）を指し、その `Content` 内に子となる `Think` のIDリストを保持することで階層的な親子関係を構成します。

### 1.1 TTNotifyBase（変更通知基底 - 継承元: なし）
メモリ上の状態変更を React 等のビュー層へ伝えるための Observer パターンを提供します。
*   `_parent: TTNotifyBase | null`: 親オブジェクトへの参照。
*   `NotifyUpdated(propagateParent = true)`:
    *   自身のリスナーを発火します。
    *   `propagateParent === true` で親がある場合、親の `NotifyUpdated(false)` を再帰的に呼び出し、親のプロパティ更新（UpdateDateの変更）を発生させずに通知のみを伝播させます。

### 1.2 TTObject（永続化オブジェクト基底 - 継承元: TTNotifyBase）
*   `ID: string`: 識別子。
*   `Name: string`: タイトル。
*   `UpdateDate: string`: 状態変更時のタイムスタンプ。
*   `NotifyUpdated(updateProperty = true)`:
    *   `updateProperty === true` の場合、`UpdateDate` を現在時刻文字列で更新します。
    *   時刻書式: `yyyy-MM-dd-HHmmss-mmm-rand` (例: `2026-06-06-105608-012-a8f9`。ミリ秒とランダム4文字を含む一意識別キー)

### 1.3 TTCollection（コンポーネントコレクション基底 - 継承元: TTObject）
*   `_children: Map<string, TTObject>` で子ノードを一元管理します。
*   `ItemSaveProperties: string`（カンマ区切りのプロパティ名）に指定されたフィールドのみを抽出し、CSVデータとしてシリアライズ（`SerializeToCsv`）および復元（`DeserializeFromCsv`）する汎用メソッドを提供します。

### 1.4 TTThink（個別データアイテム - 継承元: TTObject）
*   `ContentType`: `memo` | `thought` | `table` | `links` | `chat` | `nettext`
*   `Content`: 本文プロパティ。
    *   **タイトル自動抽出**: `Content` の setter 処理時、コンテンツの第1行目（改行コード `\n` で分割された最初の行）を自動取得し、先頭のシャープ `^#+\s*` やスペースを除去した文字列を `Name` （タイトル）にセットします。
*   `IsDirty: boolean`: メモリ上の値（`_content`）と保存済みの値（`_savedContent`）を比較し、変更の有無を検出します（改行コードの `\r\n` と `\n` の差異は正規化して比較）。

### 1.5 TTVault（保管庫ルート - 継承元: TTCollection）
保管庫全体のデータ管理を司る最上位のコレクションクラスです。
*   `VaultName: string`: 保管庫の識別名（LocalFS ではディレクトリ名、BigQuery ではテーブル識別子）。
*   `DataFolder: string`: ローカルFS上のルートフォルダパス。
*   ストレージ（LocalFSやBigQuery）からのデータロード・保存、および `Thought` の条件に基づくフィルタリングや全文検索による `Think` の抽出処理を統括します。

#### VaultName のストレージ別使用方法

`VaultName` は、接続するストレージバックエンド（LocalFS または BigQuery）に応じて、以下のようにマッピングされて使用されます。

##### 1. ローカルファイルシステム (LocalFS / Electron) での使用
ローカルFS上では、`VaultName` はデータ保存用の親ディレクトリ名として機能します。
*   **ファイル配置パスの構成**:
    `{DataFolder}/{VaultName}/{ContentType}/{ID}.md`
    （※環境によっては `{VaultName}/{ID}.json` などフラットに保存される場合もあります）
*   **具体例** (`VaultName` が `"vault"` の場合):
    *   `memo` タイプのデータ: `ThinktankLocal/vault/memo/2026-06-08-120000.md`
    *   `thought` タイプのデータ: `ThinktankLocal/vault/thought/2026-06-08-130000.md`
*   **特徴**:
    *   `VaultName` を変更することで、ローカル上の参照ディレクトリ（保管庫フォルダ）が切り替わります。
    *   配下に `ContentType` ごとのフォルダが自動作成され、データは `{ID}.md` という個別のテキストファイル（あるいはメタデータ込みのJSON）として永続化されます。

##### 2. BigQuery (PWA / クラウドモード) での使用
BigQuery上では、`VaultName` は指定されたデータセット内のテーブル名（テーブル識別子）として機能します。
*   **テーブル修飾名**:
    `[GCPプロジェクトID].[データセットID].[VaultName]`
    *   データセットIDは通常 `thinktank` に固定されます。
*   **具体例** (`VaultName` が `"vault"` の場合):
    *   参照されるテーブル: `thinktank.vault`
*   **特徴**:
    *   `VaultName` を切り替えることで、BigQuery内の異なるテーブル（例: `thinktank.vault` や `thinktank.work_vault` など）に接続先が切り替わります。
    *   テーブル内では、`category` カラム（`ContentType` に対応）でデータ種別が区別され、全データが1つのテーブルにレコードとして集約されて管理されます。

## 2. 各 ContentType のテキストフォーマット仕様

`ContentType` ごとに本文（`content`）の記述規則が決まっており、[thinkFormat.ts](file:///c:/Users/gogow/Documents/ThinktankWebCC/src/utils/thinkFormat.ts) によって処理されます。

### 2.1 memo / nettext (自由テキスト形式)
1行目がタイトル（自動抽出対象）となり、2行目以降は通常のMarkdown形式のテキストです。

```markdown
# 読書メモ：デザインパターン
Observerパターンについて整理する。
変更通知を購読者に通知するデザインパターン。
```

### 2.2 chat (AI対話記録形式)
AIアシスタントとの会話ログを記録します。
*   **フォーマット**:
    ```markdown
    対話タイトル（タイトル行）
    ## ユーザーの質問1
    AIの回答1。Markdown形式が使えます。

    ## ユーザーの質問2
    AIの回答2。
    ```
*   **パース規則 (`parseChat`)**:
    *   `## ` で始まる行を `role: 'user'` にマージします。
    *   それ以外の行（次の `## ` が現れるまで）を `role: 'assistant'` のメッセージとして結合し、`ChatMessage[]` を復元します。

### 2.3 links (リンク集形式)
外部URLやローカルファイルパスのリンクをリスト化して管理します。
*   **フォーマット**:
    ```markdown
    リンク集タイトル（タイトル行）
    * [Google](https://google.com)
    * [ローカル資料](C:\path\to\doc.pdf)
    ```
*   **パース規則 (`parseLinks`)**:
    *   タイトル行をスキップし、`* ` で始まる行から Markdown リンクの正規表現 `^\[([^\]]+)\]\(([^)]+)\)$` でラベルとURLを抽出します。

### 2.4 thought (テーマ・コレクション形式)
複数のThinkデータ、あるいは動的な検索・フィルター条件を保持して集約するための仮想コレクション表現です。
*   **フォーマット**:
    ```markdown
    > コレクションタイトル
    > Keyword：LLM
    > 更新日：2026-06-01, -1w
    >> 検索語：AI
    * 2026-05-30-120000
    * 2026-05-31-153000
    ```
*   **パース規則 (`parseThought`)**:
    *   `* ` で始まる行: thoughtに明示的に含める個別Thinkの `ID` リスト（`ids`）。
    *   `> ` で始まる行: フィルターパラメータ（Keyword, 作成日, 更新日）。
    *   `>> ` で始まる行: 全文検索パラメータ（検索語, 作成日, 更新日）。
    *   日付条件の右辺（範囲）には `-1w` (1週間前) などの相対指定が記述できます。

## 3. table 形式（表データ）のフォーマット仕様

CSVベースの表データを、コメントなどのファイル構造を維持しながら表現するための独自仕様です。[tableFormat.ts](file:///c:/Users/gogow/Documents/ThinktankWebCC/src/utils/tableFormat.ts) によって処理されます。

### 3.1 フォーマット定義
```markdown
テーブルのタイトル（1行目）
# コメント行（データから除外されますが、シリアライズ時も位置が維持されます）
; コメント行

> key,current,default,type,description
RowKey1,true,true,boolean,左パネル表示
RowKey2,false,false,boolean,行番号表示
```

*   **列定義ヘッダー**: 行頭が `>` で始まる最初の行。カンマ区切りで列名が定義されます。
*   **データ行**: 通常のCSV形式の行。
*   **コメント行**: `#` または `;` で始まる行。
*   **空行**: 何もない空の行。
*   **パース規則**: RFC 4180 準拠のCSV行パーサー（`parseCsvLine`）を使用し、ダブルクォートで囲まれた値の中にあるカンマやダブルクォートのエスケープを正しく処理します。

## 4. 構造維持部分更新（構造維持シリアライズ）

UI設定（`__tt_ui_state__`）やショートカット（`__tt_shortcuts__`）はシステム用の `table` 形式 Think としてストレージに永続化されます。
ユーザーが Monaco Editor 等を用いてファイル内のコメントや並び順を手書き編集することがあるため、設定更新による自動書き戻し時に**コメントや空行の構造を壊さない**ように更新する必要があります。

### 4.1 アルゴリズム (`updateTableContent`)
1.  元のテキストコンテンツを `parseTableContent` で解析し、`TableSection`（列名・行データ、およびコメントや空行を含むオリジナルの行順リスト `rawLines`）を作成します。
2.  `rawLines` のうち `type === 'data'` の行について、指定された主キー列（例: `key`）の値を取得します。
3.  主キーが更新対象のマップ（`updates`）に含まれる場合、該当行の対象列（例: `current`）の値のみを書き換えた新しいデータ行配列（`newRows`）を生成します。
4.  `tableSectionToContent` を用いて再シリアライズします。
    *   `rawLines` の行順序に従ってテキストを走査します。
    *   コメント行や空行は、元のテキストをそのまま出力します。
    *   列定義行およびデータ行（`type === 'data'`）を出力する際は、更新後の `newRows` から値を抽出し、CSVエスケープ処理を施してカンマ区切りで出力します。その際、列定義ヘッダーの項目表示位置にできるだけ合わせます。
