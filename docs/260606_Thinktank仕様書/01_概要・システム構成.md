# Thinktank アプリケーション仕様書：01. 概要・システム構成

本ドキュメントは、ナレッジ管理・思考支援アプリケーション「**Thinktank**」のシステム概要および構成について定義します。

---

## 1. アプリケーション概要

**Thinktank**は、日々のメモ、データベース（表）、AIとのチャット履歴などを統合し、それらを仮想的なテーマ（コレクション）として紐付けながら思考を深めるための「ナレッジ管理・思考支援システム」です。

### 主な特徴
1.  **4パネルによるシームレスなUI**: データの抽出、構造の俯瞰、詳細な作業・編集、AIとの対話の4つのコンポーネントが1つの画面で連携します。
2.  **BSPツリーによる柔軟な画面分割**: メイン作業領域（WorkoutPanel）を二分空間分割（BSP）ツリーによって再帰的に分割し、複数のデータを並行して編集・閲覧できます。
3.  **複数バックエンドサポート**: Localモード（Electron）とOnlineモード（Express/BigQuery）の双方に対応したデータ永続化モデルを持ちます。

---

## 2. 起動モードと動作仕様

本アプリケーションは、利用環境に応じて以下の2つのモードで動作します。

| モード | 動作環境 | データ保存先 | 特徴 |
| :--- | :--- | :--- | :--- |
| **Local モード** | Electron アプリケーション | ローカルの暗号化/プレーン JSON ファイル<br>(`app.getPath('userData')/thinktank/vault/*.json`) | オフライン動作可能。ローカルのファイルシステムを直接操作し、高速な応答性を有する。<br>クラウドデータベースとの同期のon/offを設定可能。 |
| **Online モード** | Web ブラウザ | Google BigQuery (`thinktank.vault` テーブル) | クラウド上のデータベースに直接接続し、デバイスを問わず同一のデータにアクセス可能。Express サーバー経由で通信。 |

## 3. システム構成・アーキテクチャ

システム全体の連携構成は以下の通りです。

```mermaid
graph TD
    subgraph Client [クライアント領域 (Vite + React + TS)]
        App[App.tsx] --> Layout[AppLayout.tsx]
        Layout --> Thinktank[ThinktankPanel]
        Layout --> Overview[OverviewPanel]
        Layout --> Workout[WorkoutPanel]
        Layout --> ReThink[ReThinkPanel]
        
        TTApp[TTApplication.ts] <--> TTUIState[TTUIStateManager.ts]
        TTApp <--> TTShortcut[TTShortcutManager.ts]
        TTApp <--> TTVault[TTVault.ts / TTThink.ts]
        
        TTVault <--> StorageManager[StorageManager.ts]
    end

    subgraph Desktop [デスクトッププロセス (Electron)]
        StorageManager -- window.electronAPI (IPC) --> ElectronMain[main.cjs / preload.cjs]
        ElectronMain <--> Local[(ローカル JSON ファイル群)]
    end

    subgraph Cloud [クラウドバックエンド (Express Server / Node.js)]
        StorageManager -- HTTP API (/api/bq/*) --> Express[server/index.ts]
        Express <--> BigQuery[(Google BigQuery: thinktank.vault)]
        Express <--> GoogleDrive[(Google Drive API)]
        Express <--> AIService[AI API: Anthropic / OpenAI / Gemini]
    end
    
    ElectronMain -- syncFromServer --> Express
```

## 4. 技術スタック

*   **Core Front-end**: React 18, TypeScript, Vite
*   **Aesthetics & Styling**: CSS Grid / Flexbox, CSS Variables, Curated Harmony Palette (Vanilla CSS)
*   **Editor Component**: Monaco Editor (for TypeScript/Markdown/CSV Editing)
*   **Desktop Shell**: Electron
*   **Server Platform**: Node.js, Express
*   **Cloud Storage & DB**: Google BigQuery, Google Drive (Google APIs Node.js Client)
*   **AI Models**: Anthropic Claude SDK, OpenAI SDK, Google Generative AI SDK

## 5. ディレクトリ構造と主要ファイルの役割

プロジェクトの主要なファイル構造と、再構築時に維持すべき責務の分離は以下の通りです。

```
ThinktankWebCC/
│
├── electron/                   # デスクトップ環境 (Electron)
│   ├── main.cjs                # メインプロセス：IPC受信、ローカルFSのCRUD、Expressとの同期
│   └── preload.cjs             # レンダラーとのブリッジ API 露出
│
├── server/                     # クラウドバックエンド (Express Server)
│   ├── index.ts                # サーバー起動、ミドルウェア設定、APIルートの登録
│   ├── routes/
│   │   ├── bigqueryRoutes.ts   # BQ ストレージ連携 API ルート (/api/bq/files/*)
│   │   ├── chatRoutes.ts       # SSE ストリーミングチャット API ルート (/api/chat/messages)
│   │   └── driveRoutes.ts      # Google Drive アップロード API ルート (/api/drive/upload)
│   └── services/
│       ├── BigQueryService.ts  # BigQuery の CRUD 処理、MERGE 文による並列更新リトライ
│       ├── ChatService.ts      # 複数 AI プロバイダー対応 SSE ストリーミング処理
│       ├── driveService.ts     # Google Drive フォルダ作成・ファイルアップロード
│       └── VectorStoreService.ts # コサイン類似度計算用（現在ダミー化・非推奨）
│
└── src/                        # フロントエンド (React / TypeScript)
    ├── main.tsx                # エントリーポイント
    ├── App.tsx                 # アプリの初期化、グローバルイベントリスナー登録
    │
    ├── types/
    │   └── index.ts            # AppMode, ContentType, MediaType, ItemMeta, ChatMessage 等の共通型定義
    │
    ├── models/                 # データ階層モデル
    │   ├── TTNotifyBase.ts     # Observer パターンの基底クラス（React 連携用）
    │   ├── TTObject.ts         # ID/Name/UpdateDate 等の共通プロパティ・タイムスタンプ管理
    │   ├── TTCollection.ts     # CSVシリアライズ・デシリアライズ可能な子ノード管理クラス
    │   ├── TTVault.ts          # 保管庫クラス。TTVault > Thoughts > Thought > Think の階層制御
    │   └── TTThink.ts          # 個別データアイテム。タイトル行抽出、dirty管理、StorageManager連携
    │
    ├── views/                  # ビューモデル（UI状態・ロジック管理）
    │   ├── TTApplication.ts    # ルートビューモデル。4パネルモデルの統合、Open/Link操作
    │   ├── TTUIStateManager.ts # UI設定（__tt_ui_state__）の管理、状態変更通知、Undo/Redo
    │   ├── TTShortcutManager.ts# キー・マウス・ホイールの解釈、ExMode、ディスパッチ、競合回避
    │   ├── TTActions.ts        # アクションレジストリ、同期/非同期のハイブリッド実行
    │   ├── TTFocusedPanelActions.ts # パネル開閉、Monaco見出し移動・段階的折りたたみロジック
    │   ├── TTWorkoutPanel.ts   # Workout パネルのツリー管理、テキストエディタ詳細設定
    │   └── TTWorkoutArea.ts    # 単一エディタ領域の管理（MediaType、ResourceID、dirty）
    │
    ├── components/             # React コンポーネント群
    │   ├── Layout/             # AppLayout, MenuRibbon, PanelArea, Splitter
    │   ├── ThinktankPanel/     # 左パネル：フィルタ、検索、Thoughts一覧
    │   ├── OverviewPanel/      # 中央左パネル：データグリッド、関係グラフ、チャット
    │   ├── WorkoutPanel/       # 中央右パネル：BSPツリーの再帰描画、エディタ、ツールバー
    │   └── ReThinkPanel/       # 右パネル：AI対話 CLI、履歴
    │
    └── utils/                  # ユーティリティ
        ├── thinkFormat.ts      # chat, links, thought 形式テキストのパース・シリアライズ
        ├── tableFormat.ts      # table 形式の RFC 4180 CSVパース、構造維持部分更新
        ├── keyboardUtils.ts    # キーコード・マウス・ホイールの文字列正規化・分割
        ├── dateUtils.ts        # 日付範囲（-1w などの相対指定含む）のパース・計算
        └── getFocusName.ts     # フォーカス要素から focusable 属性名を特定する
```
