# Thinktank アプリケーション仕様書：04. 状態管理・アクション・ショートカット仕様

本ドキュメントは、アプリケーションにおけるUI状態（設定値）の同期、アクションの登録・実行、キーボード・マウスショートカットの処理、およびMonaco Editor上の独自見出し操作アルゴリズムについて定義します。

## 0. アクションと状態変数（Status）のID命名規則

本アプリケーションにおけるアクション（Action）および状態変数（Status）のID命名規則は以下のように定義されます。

1. **基本形式**
   Action および Status は、ともに `*.*.*` 形式のID（例：`TextEditor.WordWrap.IsVisible`）を基本とします。
2. **Statusの読み取り専用化**
   Statusは原則として「読み取り専用（Read-Only）」とし、外部から直接値を代入・変更することを禁止します。
3. **Statusの変更方法**
   Status値の変更は必ず対応する **Action** を経由して実行します。その際、状態を変更するActionのIDは、**`{Status ID}.*`** 形式（例：`TextEditor.WordWrap.Toggle` や `ThinktankPanel.Mode.Set` など）とします。

## 1. UI状態管理（TTUIStateManager）

アプリケーションの設定（フォントカラー、開閉状態、表示モードなど）は、一元化された状態マネージャーによって管理され、システムThink `__tt_ui_state__` にテーブル形式で永続化されます。

### 1.1 設定項目定義の一元集約（`PROP_SPECS`）
新たな設定値を追加する場合、`PROP_SPECS` マップオブジェクトに定義を1つ追加するだけで、ロード・保存・バリデーション・シリアライズの仕組みが自動的に適用されます。

*   **設定プロパティスキーマ (`PropSpec` インターフェース)**:
    *   `panel`: 反映先の対象パネル（`ThinktankPanel`, `OverviewPanel` など）。
    *   `default`: デフォルト値（文字列）。
    *   `type`: `boolean` | `string` | `color` | `json`
    *   `candidates`: 入力検証用の正規表現（例: `^(true|false)$`）。
    *   `description`: 説明文。
    *   `get(app)`: 現在のアプリ状態から設定値を文字列で取得する関数。
    *   `set(app, value)`: 設定値をアプリ状態へ適用する関数（※適用内では `NotifyUpdated` は呼ばない）。

### 1.2 Pub/Sub による変更通知
*   `addListener(key, callback)` / `removeListener(key, callback)`: 指定したキーに対するプロパティ変更イベントを購読します。
*   **一括 / ワイルドカード通知**:
    *   特定のキー変更時、そのリスナーを呼び出すだけでなく、パネル単位（例: `ThinktankPanel.*`）のワイルドカードリスナー、およびグローバルリスナー（`*`）も同時にディスパッチします。
    *   これにより、コンポーネント自身が自律的に再描画（`NotifyUpdated`）を検知できます。

### 1.3 パフォーマンス＆履歴管理
*   **デバウンス保存**: 設定値の変更が発生すると、`500ms` の遅延タイマーを伴うデバウンス処理（`_scheduleSave`）を経て `localStorage` および `__tt_ui_state__` への書き込みが実行されます。
*   **Undo / Redo 機能**:
    *   最大50件のUI状態テキストを履歴スタック（`_undoStack` / `_redoStack`）で保持します。
    *   `applyProperty()` などで値が書き換わる直前に、現在のシリアライズ状態を `_undoStack` にプッシュします。

## 2. アクションの管理と実行（TTActions）

本システムは、ショートカット等からキックされる処理を「アクション」として登録し、同期・非同期の双方に対応した実行パイプラインを提供します。

### 2.1 データ型
```typescript
export interface TTAction {
  ActionID: string;
  Description?: string;
  Category?: string;
  Completion: (item: TTActionItem) => void | Promise<void>;
}

export interface TTActionItem {
  ActionID: string;
  Result: string;  // 実行完了後に表示するステータス文字列
  Allow: boolean;   // 同一イベントで後続のショートカットの実行を許可するか (通常は false)
}
```

### 2.2 非同期実行制御（ハイブリッド実行）
`TTActions.Execute(actionId)` の呼び出し時、アクション定義の `Completion` を実行します。
*   `Completion` が `Promise` を返した（非同期アクション）場合:
    *   即座にステータスバー等の表示状態を `[実行中...]` に更新します。
    *   `Promise` の `resolve` または `reject` を待ち受け、完了後にステータス表示を `Result` （またはエラー内容）に自動更新します。
*   `Completion` が同期的に終了した場合:
    *   即座に `Result` 文字列を書き出します。

## 3. ショートカット・イベント制御（TTShortcutManager）

キーボード、マウス、マウスホイールのすべてのイベントを正規化した文字列に変換し、現在の「フォーカス先」と「ExMode（一時的モディファイア）」に適合するアクションをディスパッチします。

### 3.1 イベントの正規化 (`keyboardUtils.ts`)
*   **モディファイア順序の固定**: キーボードイベントは、常に小文字の `ctrl+alt+shift+meta+{キー名}` の順序にソートして正規化します（例: `Ctrl + Z` → `ctrl+z`）。
*   **マウスイベントの文字列化**:
    *   クリック → `left1`、ダブルクリック → `left2`、右クリック（コンテキストメニュー） → `right1`
    *   モディファイア修飾を付加可能（例: `shift+left1`）。
*   **ホイールイベントの文字列化**:
    *   上スクロール → `wheelup`、下スクロール → `wheeldown`
    *   モディファイア修飾を付加可能（例: `ctrl+wheelup`）。
*   **複数キー定義の分割**:
    *   ショートカット定義の `key` 列が `ctrl+z|ctrl+y` のように `|` で区切られている場合は分割して解釈します。
    *   ダブルクォートで囲まれている部分はエスケープとして扱い、`|` 自体の登録を可能にします（例: `"ctrl+|"`）。

### 3.2 フォーカスと ExMode によるアクティブテーブル構築
実行速度の最適化のため、イベント発生時に全定義を検索するのではなく、状態変化時にフィルタ済みの一致候補インデックス（`_activeTable`）をキャッシュします。
*   **フォーカス状態の変更**: `focusin` イベントを requestAnimationFrame でデバウンス検知し、`document.activeElement` が属するパネルのカラム識別子を取得して `_currentFocus` を決定します。
*   **ExMode 変更時のキーマージ**:
    *   一時モディファイアモード（`ExMode`）が有効である場合、そのモードに応じた修飾キー（`Status.ExModeModKey`）を、登録されているキーバインドに対して自動的に付加してディスパッチ対象とします（例: `ExPanel` モード中に `o` が押されたら、内部で `ctrl+alt+o` などにマージして合致判定）。

### 3.3 ディスパッチ順序と入力フォーム競合制御
イベントハンドラーは `document.addEventListener` の `capture: true` （キャプチャフェーズ）で登録され、ブラウザの既定の動作や他コンポーネントよりも先に実行されます。
処理は以下の順で判定され、ヒットした時点で処理を中断します（`stopPropagation()`）。

1.  **フォーカス固有ショートカット**: 定義の `focus` 列が現在のフォーカス値と部分一致（前方/後方一致、ワイルドカード対応）する定義を実行。
2.  **ExMode グローバルショートカット**: 現在 `ExMode` が有効、または対象アクションが `ExMode` を起動・変更するものである場合、入力コントロール内であっても強制実行。
3.  **通常グローバルショートカット**: `focus` が `*` の定義。ただし、フォーカスが `input`, `textarea`, `select`, または `contenteditable="true"` の要素にある場合は、誤入力を防ぐためディスパッチを無効化します（Monaco Editor 用のアクションのみは例外的にバイパスして処理されます）。

## 4. Monaco Editor 専用見出し操作アルゴリズム

テキストエディタ（Monaco Editor）での作業効率向上のため、Markdown見出し構造（`#`の数）を利用した独自の折畳・カーソル移動アクションが実装されています。

### 4.1 見出し行の属性取得 (`getHeadingAttributes`)

エディタ上のドキュメント（Markdown構造）から各見出しのメタデータを解析し、アウトライン構造やインデックス情報を生成するアルゴリズムです。

1.  **全行走査**:
    ファイルの先頭（1行目）から末尾行に向けて、すべての見出し行（行頭が `#` で始まる行）を順に走査します。
2.  **属性データの抽出**:
    検出された各見出し行について、以下の項目で構成される属性データを抽出し、配列として格納します。
    *   **行先頭の文字位置オフセット (Offset)**:
        ドキュメント全体における、該当見出し行の開始位置を示す0始まりの累積文字数（Offset）。
    *   **階層構造見出し番号 (Heading Number)**:
        見出しの親子・ネスト構造をドットで区切って表現した文字列（例: `1.2.3`）。現在の見出しレベルが上位（親）に変化した際、それより下位の階層カウンターはリセットされます。
    *   **非表示フラグ (IsHidden)**:
        当該行が、それより上位の見出し行が折りたたまれている（Folding）ことによって、エディタ上で非表示（隠し状態）になっているかを示す真偽値（boolean）。
        *   ※判定方法：当該行より前（上方向）にある全見出し行 `h` について、`h` が折りたたまれており、かつ `h` の fold スコープ内に対象行が含まれる場合、非表示と判定します。

### 4.2 属性情報を利用した見出し操作プロセス

`getHeadingAttributes` によって取得した属性情報配列（`HeadingAttribute[]`）を利用することで、以下の見出し関連プロセス（操作・移動・抽出・開閉）が効率的なアルゴリズムで実現可能となります。

*   **見出し行の表示可視性判定**:
    見出し行自体の可視性は、`HeadingAttribute` の `isHidden` 属性を参照することで直接判定します（`isHidden === false` であれば表示）。一般行の場合は、その行を含む見出し行の `isHidden` に従います。
*   **特定Offsetを内包する見出し行の特定**:
    1.  属性配列から `offset <= targetOffset` を満たす見出し行を絞り込みます。
    2.  絞り込んだ中で、最もOffset値が大きい（＝ドキュメント上でカーソル位置の直前にある）見出し行を、内包する見出し行として特定します。
*   **特定Offsetの次の/前の表示見出し行の特定**:
    *   **前の表示見出し**: `offset < targetOffset` を満たす見出しを後ろ（Offsetの降順）から逆方向に走査し、`isHidden === false` である最初の行を特定します。
    *   **次の表示見出し**: `offset > targetOffset` を満たす見出しを前（Offsetの昇順）から順方向に走査し、`isHidden === false` である最初の行を特定します。
*   **特定見出し行の親見出し行の特定**:
    1.  対象見出しの `headingNumber`（例: `1.2.3`）の末尾セグメントをドット区切りで1つ除去し、親の番号（例: `1.2`）を算出します。
    2.  属性配列から、`headingNumber` が算出値と完全一致するものを特定します（レベル1の場合は親が存在しないため空）。
*   **特定見出し行の子見出し行の特定**:
    1.  対象見出しの `headingNumber` を親の番号 `P`（例: `1.2`）とします。
    2.  属性配列から、`headingNumber` が `P.` で始まり、かつドットで分割した際の要素数が `P` の要素数よりちょうど1つ多いもの（例: `1.2.1`, `1.2.2` など）をすべて抽出します。
*   **特定階層レベルの見出し行の特定**:
    1.  指定する階層レベル（深さ）を `L` とします（例: レベル2であれば `2`）。
    2.  属性配列から、`headingNumber` をドット（`.`）で分割した際の要素数が `L` と等しいものをすべて抽出します。
*   **段階的展開・折りたたみ**:
    *   **段階的展開 (`TextEditor.Folding.OpenEachLevel`)**:
        1.  現在のカーソル位置から上方向に最も近い見出し `H`（属性配列内の `offset <= targetOffset` を満たす最大offsetの見出し）を取得します。
        2.  `H` 自体が折りたたまれている（Monacoの `isLineFolded(H)` が真）場合は、その行を展開（Unfold）して終了します。
        3.  展開されている場合、`H` の子見出し（属性配列内において、`headingNumber` が `H.headingNumber.` で始まり、かつ階層レベルが `H` より1つ深い見出し）を走査し、折りたたまれているものをすべて展開して終了します。
        4.  それでも展開対象が見つからない場合は、孫見出し（レベル `+2`）、曾孫見出し（レベル `+3`）へと順に深さを下げて走査し、最も浅い階層の折畳状態を段階的に展開します。
    *   **段階的折りたたみ (`TextEditor.Folding.CloseEachLevel`)**:
        1.  現在のカーソル位置から上方向に最も近い見出し `H` とそのスコープ（属性配列内で `H.headingNumber` を前方に含む子孫見出しの集合）を特定します。
        2.  子孫見出しについて、最深レベル（最大 `6`）から順に親方向（`H` のレベル `+1` まで）に向かって走査します。
        3.  該当レベルの展開されている（折りたたまれていない）見出しが見つかった場合、その階層の見出しをすべて折りたたんで終了します。
        4.  スコープ内のすべての子孫見出しがすでに折りたたまれている場合は、親である `H` 自体を折りたたみます。
