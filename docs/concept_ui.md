# Thinktank ── UI コンセプト

> 本ドキュメントは [concept.md](concept.md) の方針（コンセプト・3本の柱）を **UI としてどう実現するか** をまとめたもの。
> 現状 UI（TTWeb260418）の継続性よりも、**concept.md の方針実現を優先**して方向を決める。
> 構成: 「現状 UI の整理（参考）」→「方針との照合（居場所の不足）」→「将来の UI 方針」。

---

## 1. 現状 UI の構成（参考 / TTWeb260418）

左から右へ並ぶ **4 パネル**を中心とした構成。詳細なツリーは `docs/structure.txt` 参照。

### 1-1. 4 パネルの役割

| 位置 | パネル | 役割 | モード（内部ID） |
|------|--------|------|-----------|
| 左端 | **Thinktank** | 全 Think の制御・一覧の起点 | Thought一覧(`thoughts`) / Think一覧・フィルタ(`filter`) / 検索(`search`) / AI相談(`chat`) / 設定(`settings`)。既定は `thoughts` |
| 左2 | **Overview** | 特定の Thought を掘り下げる | Think一覧(`datagrid`) / Thought分析・グラフ(`graph`) / AI相談(`chat`) / 設定(`settings`) |
| 中央 | **Workout** | コンテンツの編集・作業領域 | （後述の7メディア + BSP分割） |
| 右端 | **ReThink** | AI との CLI 風対話・考察 | AI相談(`chat`) / 設定(`settings`) |

→ 大まかな流れは「**一覧（Thinktank）→ 掘り下げ（Overview）→ 作業（Workout）→ 対話（ReThink）**」。
→ 各パネルのモードは **キーボードでも巡回**できる（ExMode `ExPanel` ＋ `p`/`n` で前/次モード。`TTShortcutManager`）。

### 1-2. 共通の操作部品

- **MenuRibbon（上部）**: 全選択/チェック表示/日付フィルタ/ソート設定/Thought作成/削除 等。
- **UnifiedFilterPanel**: キーワード検索＋作成日/更新日レンジ＋フィルタ履歴プルダウン。
- **ColumnSortDialog**: 表示項目とソートの設定。
- **縦リボン（各パネル左右端）**: モード切替ボタン。
- **HighlightProvider**: アプリ全体を包む、横断的なハイライト（語の強調）機構。
- **UI 状態の永続化（`TTUIStateManager`）**: 各パネルの ViewMode やパネル幅・各種設定を管理・保存。設定は候補（許容値）付きで Command モードからも変更可能。

### 1-3. Workout パネル（作業領域）の中身

- **BSP ツリーで画面を再帰分割**（左右/上下に分割、ペイン追加・消去・均等化）。
- 1 ペインを **7 種のメディアビュー**で表示し、種別に応じ切替:
  - `texteditor`(Monaco) / `markdown` / `datagrid`(表) / `card` / `graph` / `chat`
- 左の **WorkoutRibbon** は設定カテゴリ（`workout`＝分割操作 / `texteditor` / `markdown` / `datagrid` / `card` / `graph`）を選ぶ。ペインごとのメディア表示とは別に、設定対象を切り替える役割。
- 最下段 **WorkoutToolBar**: Status / Highlighter / KeyAction / Command / Translate / Reminder の各モード。左側にコマンド/テキスト入力欄（ハイライト履歴の datalist 付き）。
- キーボードショートカット体系（`TTShortcutManager` / ExMode / KeyAction バー）あり。

### 1-4. 現状 UI の特徴（評価）

- **強み**: 一覧・検索・編集・分割表示・キーボード操作が作り込まれており、「記録する／編集する」基本機能（②）の UI は充実。
- **性格**: 多機能・情報密度が高く、**操作者の習熟を前提**とした作り。リボン/モード/ショートカットが多層。

## 2. concept.md 方針との照合（UI 上の「居場所」の不足）

concept.md の 3 本の柱＋入力経路を、現状 UI に重ねたときの過不足。

| concept.md の方針 | 現状 UI の受け皿 | 過不足 |
|-------------------|------------------|--------|
| **第一の柱: 追体験（時系列タイムライン）** | 該当なし（更新時刻表示のみ） | ✕ **タイムラインの居場所が無い** |
| **第二の柱: 相関グラフ（近さ）で再アクセス** | `graph` メディア / Overview「Thought分析」 | △ 土台はあるが「近さ指標の切替」「再浮上の集約」は未 |
| **第三の柱: 文脈付き Chat（思考補完）** | AI相談モード各所 / ReThink / `chat`メディア | △ 入口が分散。「今の文脈を渡す」操作が不明確 |
| **WebText 取り込み（手動コピペ＋URL自動補完）** | 該当なし | ✕ **取り込みフォームの居場所が無い** |
| 土台: 記録の基本機能（②） | Thinktank / Workout | ◎ 充実 |

**要点:**
- 「記録・編集」は充実しているが、**concept.md の主役である「追体験」「再発見（相関グラフ）」「思考補完」を“迷わず開ける場所”が UI 上に確立されていない**。
- かつ、現状 UI は情報密度が高く習熟前提。対象（中高齢者・迷わなさ）という原則と、再設計時に折り合いをつける必要がある。

## 3. 将来の UI 方針

> 現状 UI の継続性より concept.md 方針の実現を優先する。

### 3-1. 基本骨格 ── 決定方針

- **現 4 パネルを拡張して載せる**。新しい骨格には作り替えない。
- concept.md の主役機能（追体験・相関グラフ・思考補完）は、**明示的なメニュー機能としては実装せず**、4 パネルの各役割に**分散して溶かし込む**。
- **想定ユーザーは当面「自分（中高年かつ習熟者）」**。よって Workout の高い情報密度は現状のまま維持する。中高齢者向けの簡素化は将来課題。

### 3-2. 貫く流れ ── 「興味コンテキストの受け渡し」

4 パネルは「一覧 → 掘り下げ → 作業 → 対話」の流れであり、**左から右へ“興味コンテキスト”をバトンのように渡していく**:

```
① Thinktank        ② Overview          ③ Workout            ④ ReThink
（探す・発展）  →  （ダイジェスト・追体験）→（作業・相関グラフ）→（対話・思考補完）
   全データ          渡された興味/Thought    Thought範囲           本日分の考え＋全データ/Web
```

### 3-3. 各パネルへの機能の割り当て ── 決定方針

**① Thinktank パネル（一覧 / 探索）**
- 対象は**全情報**。ここで**新しい興味対象を探し、発展**させる。
- **② へ渡す単位は Thought**。① で **Thought を開くこと＝② への受け渡し**。
  - 適切な Thought が無ければ、① で **Thought を作成してから渡す**（既存の「チェック項目から Thought 作成」を活用）。
  - 個別 Think 単位の受け渡しは設けない（常に Thought でまとめて渡す）。
- → concept.md の「再アクセス／再発見」の入口側。

**② Overview パネル（掘り下げ / ダイジェスト / 追体験）**
- ① から渡された興味対象（Thought）を **ダイジェスト**するのが目的。
- Thought には**履歴の記載**がある想定。これにより**過去思考の「追体験」**ができる。
- **新規「タイムライン」モードを追加**する（現状の Think一覧/Thought分析/AI相談/設定 に並ぶ新モード）。
  - Thought ダイジェストと配下の更新履歴を**時系列で一覧**する。各時点から本文・差分へ辿れる。
- → concept.md **第一の柱（追体験・タイムライン）** の主な居場所。

**③ Workout パネル（作業）**
- ②で絞った対象について実際の**作業・編集**を行う。
- **Thought の範囲内での相関グラフ**などはここで表示する。既存の `graph` メディアを次の3点で拡張:
  - **近さ指標の切替 UI**（意味的／作業日時／文書内リンク…をグラフ上で切替）。
  - **再浮上をグラフに集約**（「今の文脈に近い過去メモ」「しばらく触れていない束」をグラフ上や脈で提示）。
  - **ノードから本文／タイムラインへ**（ノードクリックで Think 本文や ② の追体験タイムラインへ飛ぶ）。
- **WebText 取り込みの入口**もここ。新規 Think（`nettext`）を作る操作として、本文をコピペ→URL 自動補完→保存（新規メモ作成と同じ操作系に乗せる）。
- → concept.md **第二の柱（相関グラフ・近さ）** の主な居場所。Workout の密度は維持。

**④ ReThink パネル（対話 / 思考補完）**
- **「まとめ」ボタンで AI に本日分をまとめさせる**。本日作業分の「考え」の概要、これまでとの違い、全体としての考えの変化を AI が要約して提示。
- その**まとめに添えて、外の視点（思考補完）を提示**する。全データや Web の情報を踏まえ、AI が別視点・問いを差し出す。
  - ボタンを押す＝ユーザーが求めた時なので、concept.md の「**聞いたときだけ**」（受け身・押し付けない）と整合する。
- 続けて同じ文脈付き Chat で深掘りでき、対話は `chat` として履歴に残る。
- → concept.md **第三の柱（文脈付き Chat・思考補完）** の主な居場所。

## 4. まとめ ── パネル別 機能マップ

| パネル | 役割 | concept.md の柱 | UI 上の実現 |
|--------|------|-----------------|-------------|
| **① Thinktank** | 探す・発展 | 再アクセス（入口） | 全情報から興味を探し、**Thought 単位で②へ渡す**（無ければ作って渡す） |
| **② Overview** | ダイジェスト・追体験 | 第一の柱（追体験） | **新規「タイムライン」モード**で Thought ダイジェスト＋更新履歴を時系列表示 |
| **③ Workout** | 作業 | 第二の柱（相関グラフ） | `graph` メディアを拡張（近さ指標切替／再浮上集約／ノード→本文・タイムライン）。**WebText 取り込み**の入口（新規 `nettext`） |
| **④ ReThink** | 対話・補完 | 第三の柱（思考補完） | 「**まとめ**」ボタンで本日分を AI 要約 → **まとめに添えて補完**（外の視点）。聞いたときだけ |

**貫く流れ:** ①→②→③→④ で**興味コンテキスト（Thought）を受け渡す**。3本の柱は **AI を共通エンジン**として、専用メニューではなく各パネルの役割に溶け込む。

**残課題（将来）:** 中高齢者向けの簡素化（当面は習熟者＝自分向けで Workout の密度は維持）。
