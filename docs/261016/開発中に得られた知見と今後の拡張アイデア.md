## 1. 実データ（BigQuery 5,819件 ＆ 旧ローカルVault 5,695件）変換検証から得られた重要知見

[`scripts/convert-vault/convertVault.mjs`](../../scripts/convert-vault/convertVault.mjs) により本番 BigQuery（`thinktank.vault_ver2`）の全 5,819 件をステージング環境（`.staging_vault/Thinktank/`）へ試し変換し、SHA-256 ハッシュ完全一致検証を行った過程で以下の事実が判明しました（詳細は [`データ変換検証レポート_BigQuery_to_VaultV1.md`](./データ変換検証レポート_BigQuery_to_VaultV1.md) 参照）。

1. **本文（`body`）の完全無損失保持の実証**:
   - YAML frontmatter の閉じ `---` 以降の本文スライスを一切加工せず保持する [`shared/vaultFormat.ts`](../../shared/vaultFormat.ts) の実装により、5,819 件すべての本文 SHA-256 ハッシュが **不一致 0 件（100% 完全一致）** となりました。
2. **`metadata` 列の異種フォーマット混在と `rawMetadata` 退避の有効性**:
   - BigQuery 上で `metadata` を持つ 90 件のうち、73 件は構造化 JSON/YAML オブジェクトでしたが、17 件は標準 JSON/YAML オブジェクトとして直接解釈できない自由形式テキストまたは特殊構造でした。
   - `<thinkid>.support.json` の `rawMetadata` 退避フィールドを用意したことで、17 件も含め **全 90 件を 1 バイトも欠損させずに `.support.json` へ分離** できました。
3. **旧ローカル Vault と BigQuery 間の差分（39件 vs 5件）**:
   - `%APPDATA%\thinktank\thinktank\vault_ver2`（5,695件）と BigQuery（有効 5,504件 + 削除済 315件）を突合したところ、**旧ローカルにのみ存在する `thinkid` が 39 件**、**BigQuery（有効分）にのみ存在する `thinkid` が 5 件** 存在することが分かりました。
   - **アイデア①（本番切り替え時のハイブリッド・マージ移行）**: 本番の Google Drive 正本フォルダを作成する際は、BigQuery の 5,819 件をベースにしつつ、旧ローカルのみに存在する 39 件も「ローカル救出分」として自動的に取り込むオプションを `convertVault.mjs` に追加すると、過去の未同期メモも一切取りこぼさずに移行できます。

## 2. AI CLI 設定隔離実行とハイブリッド運用のアイデア

1. **設定隔離サンドボックス（[`electron/aiCliRunner.cjs`](../../electron/aiCliRunner.cjs)）の効果**:
   - `claude`, `codex`, `gemini` の 3 つの CLI がすべてローカル PC 上で利用可能であることを確認しました。
   - 一時ディレクトリの空フォルダ（`os.tmpdir()/thinktank-ai-cli-sandbox`）を `cwd` とし、`claude -p --setting-sources ""` や `codex exec --skip-git-repo-check --sandbox read-only -` で起動することで、リポジトリ内の開発用 `CLAUDE.md` 等の混入を防ぎ、純粋に `.thinktank/prompts/<profileId>/` のドメインコンテキストだけで応答させることができます。
2. **アイデア②（専門 Agent ごとの CLI / モデル割り当て機能）**:
   - 現在の `.thinktank/prompts/<profileId>/profile.json` の `agents` 定義に、任意の `preferredCli?: 'claude' | 'codex' | 'gemini'` フィールドを持たせることで、
     - **Regulatory / Clinical / 対話重視の Agent** → `claude`
     - **Evidence 整合性チェック / 構造化データ・表検証 Agent** → `codex`
     - **大量の関連資料を横断要約する Portfolio / Strategy Agent** → `gemini`
     のように、1 つの Bundle の中で複数のローカル AI CLI の得意分野を組み合わせる「マルチ CLI オーケストレーション」が追加コストなしで実現できます。

## 3. 「業務管理」と「高齢者思考・生活支援」のプロンプト差し替え運用に関するアイデア

1. **同一データ構造（Promotion / Gate / Ledger）の二面活用**:
   - ソースコード側のデータ構造（`PromotionCandidate`, `PromotedRecord`, `GateRecord`, `DomainEvent`）を一切変えずに、[`shared/domainProfile.ts`](../../shared/domainProfile.ts) と `.thinktank/prompts/` の差し替えだけで、
     - **再生医療 治験入り業務管理（`clinical-trial`）**: `Decision（意思決定）`, `Evidence（根拠資料）`, `Risk（リスク）`, `Program Gate`, `Compliance Ledger`
     - **高齢者 思考・生活支援（`elderly-support`）**: `決めたこと（ご本人の決定）`, `大切な記録・連絡先`, `気をつけること・心配事`, `進みぐあい・安心確認`, `確認・記録のあゆみ`
     へと意味づけと AI の口調・ガードレールが完全に切り替わることを確認しました。
2. **アイデア③（Bundle 単位でのプロファイル固定機能）**:
   - 現在はアプリ全体の設定（または Seeds パネル上部のセレクタ）でアクティブプロファイルを切り替えていますが、`<bundleId>.support.json` の `operations.profileId` にその Bundle 固有のプロファイル ID を記憶させておけば、**同じ Vault 内で「仕事用の治験プロジェクト Bundle」と「家族・親の生活支援 Bundle」を混在させ、Bundle を開いた瞬間に自動で対応する AI プロファイルへ切り替わる** 運用も可能になります。
3. **アイデア④（引用元更新時の `needs_revalidation` を活用した「生活変化の見守り通知」）**:
   - 治験業務管理では「根拠メモ（CMC規格書や非臨床報告書）が書き換わったときに、過去の Decision を『根拠再確認待ち (`needs_revalidation`)』にする」ために実装した機能ですが、
   - 高齢者支援プロファイルでは、**「お薬手帳メモ」や「主治医からの指示メモ」が更新されたときに、それに紐づく「毎日の生活の段取り（Action / Decision）」に自動で『お薬・指示のメモが新しくなりました。やり方を確認しましょう』と優しい通知を出す仕組み** としてそのまま機能します。

## 4. Web版 ⇔ 中継役PC（Firestore E2EE 中継）に関するアイデア

1. **アイデア⑤（QRコードによるワンタップ・ペアリング）**:
   - 現在 [`DomainProfileSettingsPanel.tsx`](../../src/components/ThinktankPanel/DomainProfileSettingsPanel.tsx) に中継役PCの `deviceId` と `pairingSecret`（AES-256-GCM 鍵導出用シークレット）を表示していますが、これを QR コード（または `#relay=...` フラグメント付き URL — サーバーには送信されない URL ハッシュ部）として出力すれば、出先のノートPCやタブレットから数秒で E2EE ペアリングが完了します。
