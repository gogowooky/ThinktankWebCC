# 思考支援を使いやすくする追加UI案

作成日：2026-09-08  
位置づけ：実装済み機能を踏まえた改善案。ここに示す追加・変更は、今回の文書作成では実装していない。

## 1. 優先する方向

管理項目を増やすより、「どの相談か」「今どうなっているか」「次に何をすればよいか」を、少ない操作で分かるようにする。キーを覚えなくても使えることを基本とし、本人の好みに応じて情報量を変えられるようにする。

担当パネルの切り替えはAIが担う。ユーザー向けには、パネル間を移動するボタンを増やすより、現在の相談を続けやすくする。

## 2. 現在あるUIを活かす

| 実装済みのUI | 改善するときの考え方 |
|---|---|
| 相談名・担当・状態・対象Bundleの表示 | 相談名を主にし、技術的なタグは補助情報にする |
| 「前回・現在・次を確認する」の折り畳み表示 | 最も必要な「次」を初めから短く見せる |
| 説明の長さの選択 | そのまま活かし、同じ設定を別の場所に重複して作らない |
| Bundle分析の「この課題の状況」 | 再開の入口として使い、別のダッシュボードを増やしすぎない |
| 保存・読み込みの再試行 | 成功時も含めて状態を見つけやすくする |
| Paneの「結果を相談につなぐ」 | 反映先と渡す内容を確認しやすくする |
| HTML資料の文字サイズ・鮮度案内 | 現状を活かし、管理操作はAIChatへまとめる |

## 3. 最優先の3件

### ① 文字付きの「送信」ボタンと送信方法の選択

現行のチャット入力はキー送信を中心とした構成である。入力欄の横または下に、大きめの「送信」ボタンを設ける。

- Enterで送信／Enterで改行を設定で選べるようにする。
- 入力欄に現在の操作方法を短く表示する。
- 日本語変換中の確定Enterでは送信しない。
- 応答待ちではボタンを無効化し、「考えています」「資料を確認しています」など処理に合う説明を出す。

キーボードに慣れていない方でも、何を押せばよいか分かる。変換・改行・送信の取り違えも減らせる。

### ② 相談名を中心にした、分かりやすい現在地

現行のタイトルは `PROJ:Overview｜[進行中]交流会の準備` のように情報が並ぶ。保存形式は保ち、画面では次のように分けて表示する。

```text
交流会の準備
進行中　・　全体を整理する相談
対象の資料：交流会
```

担当変更の案内には「そのまま相談を続けられます」を添える。種類・担当の英語名やIDは、必要に応じて詳細表示で確認できるようにする。

担当の変更で相談が消えた、別の仕事へ移った、と誤解しにくくなる。

### ③ 保存状況と未送信の文章を見失わない表示

現行にも保存完了やエラーの表示がある。それを、場所の変わらない小さな状態表示へまとめる。

```text
入力中 → 入力を保存中 → AIが応答中 → 応答を保存中 → 保存済み
```

- 未送信文と、送信して保存した発言を区別する。
- 相談やPaneを切り替えても、未送信文を下書きとして保持する。
- 保存失敗時には「応答をコピー」「保存を再試行」を同じ場所に出す。
- 一部の資料作成だけが失敗した場合は、保存できたものと残っている処理を示す。

「閉じても大丈夫か」が分かるようになる。毎回の確認ダイアログを増やすより、下書き保持を優先する。

## 4. 次に追加すると効果があるUI

| 優先 | 提案 | 具体的な動作と価値 |
|---|---|---|
| 中 | 「次の一手」を1行で常時表示 | 現在は折り畳みの中にある要点を、相談名の近くに表示する。未記録なら推測せず「相談して決めましょう」とする |
| 中 | 再開時の「続きから」ボタン | 前回の要点を開く。AIへの質問も行う場合は、表示だけの操作と区別する |
| 中 | 相談用の定型文ボタン | 「一つずつ説明して」「まだ決めていません」「今日はここまで」を入力欄に入れる。自動送信せず本人が編集・送信できるようにする |
| 中 | Pane成果の反映プレビュー | 宛先の相談名、参照元、追加する確認事項を示す。本人の決定を変更しないことが読み取れる表示にする |
| 中 | AIによる変更の簡潔な表示 | 「状態：進行中→待機」「担当：Workout→Overview」のように結果を示す。既存の取り消し操作につなぐ |
| 中 | 集中して相談する表示 | 現在の相談を広くし、一覧や資料を必要なときに開く。閉じた位置を覚える負担を減らす |
| 低 | アプリ内の再確認一覧 | 既存の再確認案内をまとめ、対象範囲を明示する。アプリ終了中の通知とは区別する |

## 5. すぐに増やさなくてよいUI

- 4パネルを順番に通過させる工程図や「次工程へ」の必須ボタン。
- TODO／PROJなどの分類を毎回選ばせるダイアログ。
- 全課題を一画面に並べる、大きな管理画面。
- HTMLごとに違う状態変更ボタンや操作体系。
- 本人の希望を確認せず年齢で切り替える専用モード。

これらより、現在の相談に戻れること、説明を調整できること、保存を確かめられることを優先する。

## 6. 追加後に確認すること

初めて使う方と、次の操作を一緒に確かめる。年齢だけで操作の得意・不得意を決めない。

1. キーを暗記せず、新しい相談を送信できるか。
2. 日本語変換と改行で、意図せず送信されないか。
3. 数日後に前回の内容と次の一手を見つけられるか。
4. 担当が変わっても、同じ相談の続きだと分かるか。
5. 相談の切り替えで入力中の文章を失わないか。
6. 保存できていない状態と、保存完了を区別できるか。
7. キーボード操作でもフォーカス位置が分かり、色だけに頼らず状態を読めるか。

最初の追加は「送信」「現在地」「保存・下書き」の3件を推奨する。
