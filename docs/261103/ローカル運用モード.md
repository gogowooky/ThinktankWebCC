# ローカル運用モード（PC版）

PC版（Electron）で、Firebase を使わずに Think を指定フォルダの `.md` として溜めて運用するモード。
既定は従来どおり「Firestore で使う」。Web版（スマホ等）からはローカル運用のデータは見えない（割り切り）。

## 設定画面

「Thinktank > 設定 > モード切替」（「Firebase」の上）

- ラジオボタン: 「Firestore で使う」／「ローカルで使う」
- テキストボックス: ThinkファイルFolder のパス
- 再起動ボタン（FolderSync アイコン）: 設定を保存して再起動する。ローカルの場合は起動前にフォルダを確認し、無ければ作る
- 移行ボタン（Firestore モードのときだけ使える。Firebase へのログインが必要）
  - Firestore → ローカルへコピー
  - ローカル → Firestore へコピー

モードは起動時に一度だけ決まり、切り替えは再起動で反映する（起動中に保存先が混ざらないようにするため）。
設定は userData の `app-mode.json` に保存する。

## ThinkファイルFolder の構成

```
<ThinkファイルFolder>/
  thinks/      Thinkファイル本体（<thinkid>.md と <thinkid>.support.json）
  snapshots/   スナップショット（<thinkid>/current.json）
  trash/       削除・上書きで退避した版（<thinkid>.<日時>.md など）
  system/      アプリ用（index/ 索引, prompts/ ドメインプロファイルの上書き）
```

隠し属性は付けない。一覧の高速化用の記録（meta overlay）は同期フォルダ間で共有しないよう、
フォルダごとに userData 側へ置く。

## ローカル運用での動き

- Think の読み書き・検索・削除は `ElectronStorageBackend` → IPC → `VaultEngine`（ローカル配置）
- AI CLI の MCP も同じ `VaultEngine` を参照する
- Firebase 設定・Google Drive 設定は表示しない。起動時の Firebase セッション同期と PC連携（RelayAgent）は起動しない
- スナップショット（作成・取得・一覧・削除・差分）はローカルの `snapshots/` で Firestore 版と同じ契約で動く

## ファイル消失への対策（Dropbox / Google Drive 等の同期フォルダ内に置く前提）

同時編集の衝突そのものは扱わない。ファイルが消えることだけを防ぐ。

- 保存は一時ファイルに書いてから置き換える（書きかけのファイルを残さない）
- 削除はファイルを消さず `trash/` へ日時付きの名前で移す（以前の退避を上書きしない）
- 同期ソフトの衝突コピーはアプリが消したり上書きしたりしない
- 移行で上書きされる側の版は `trash/` に日時付きで残す

## モード間でデータを混ぜない

- 起動時に前回と違うモードなら、画面側のキャッシュ（UI状態 `tt-ui-state-v4`、補助パネルの選択、IndexedDB の Vault キャッシュ）を消してから読み込む
- Firestore モードの Markdown バックアップ先と ThinkファイルFolder は別にする。同じ（または入れ子の）フォルダは拒否する

## 移行（最新を残す）

- 同じ thinkid が両方にあるときは `updatedAt` の新しい方を残す。負けた側の版は `trash/` に退避する
- 作成日時・更新日時は移行元の値を保つ
- `__tt_ui_state__`（画面状態）は移さない
- 将来のマージ機能はこの比較・退避の仕組みを広げて作る
