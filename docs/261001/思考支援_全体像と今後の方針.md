# 思考支援機能：これまでの全体像と今後の方針

作成日：2026-10-05。基準：ブランチ `TTWebCC260926BigChange`、v2.1.3（`a80cd91`）、Cloud Run リビジョン `ttweb-00043-tvc`。

思考支援の実装（2026-09-13〜09-24、`docs/ThinkSupport/01〜30`）のあと、パネル名称変更（v2.0.5〜v2.1.1）と保管庫の `vault_ver2` 移行を挟んだ。本書は再開にあたり、現在のソースから確認した全体像、文書との差分、今後の方針を一枚にまとめる。個々の仕様は `docs/ThinkSupport/` の各記録を正とし、本書はその索引と現状確認を兼ねる。

パネル名は新名称で記す（旧名：Seeds＝Overview、Develop＝Workout、Harvest＝ReThink）。`docs/ThinkSupport/` 内は旧名のままである。

## 1. 目的と二つの方向性

`docs/ThinkSupport/01` の目的は「本人が判断・行動・検証できるようにすること」であり、AIの回答そのものを成果としない。成果は、根拠のある判断、実行可能な次の行動、後から検証できる記録である。

一方、それ以前のコンセプト（旧 `docs/concept.md`。現在のリポジトリには存在しない）は、次を中核にしていた。

- **追体験**：Thought（関連を束ねた思考のまとまり）を、時間軸で振り返ること。
- **思考補完**：聞いたときだけ外の視点を差し出す、控えめな支援。

ThinkSupport の実装は「課題の開始から終了までのライフサイクル管理」に重心が移っている。再開にあたっては、どちらを主軸にするかを最初に決める必要がある（§6）。

## 3. 現在の構成

### 3.1 層と責務

| 層 | 主なファイル | 責務 |
|---|---|---|
| 資料の解決 | `src/services/ContextService.ts`、`contextTypes.ts` | Bundle → ContextSnapshot。資料範囲、本文ハッシュ、`quality: complete/partial` |
| 会話（クライアント） | `src/services/ConversationService.ts`、`components/ThoughtSupport/BundleConversation.tsx` ほか | 送信範囲の確定、回答・提案の表示、本人確認UI |
| 会話（サーバー） | `server/services/ConversationService.ts` | 本文ハッシュの照合、引用が資料本文と一字一句一致するかの検証、提案の検証 |
| AI呼び出し | `server/services/AIProvider.ts` | AIへの指示（`CONVERSATION_POLICY`）、出力JSONスキーマ、OpenAI／Geminiアダプター、無効化 |
| Agent | `server/services/AgentService.ts` | 要約・比較ジョブの保存、中断・再試行、成果物の適用 |
| 到達状態 | `server/routes/progressRoutes.ts`、`progressRecord.ts` | 本人確認済みの到達状態の追記 |
| 外部連携 | `externalRoutes.ts`、`fileSearchRoutes.ts`、`FileSearchBindingService.ts` | 書き出し記録、File Searchストアとの対応 |
| 課題・サブ課題 | `src/services/startTaskFromChat.ts`、`chatTask.ts`、`subtask*.ts`、`similarTasks.ts` | 相談の課題化、親子関係、専用Chat、類似課題の検索 |

### 3.2 データの置き場所

BQテーブル（`vault_ver2`）の列は変更していない。思考支援のデータはすべて、ThinkのYAML `metadata` に独立したキーとして追記している。どのキーも `schemaVersion` を持つ。

| キー | 置く場所 | 内容 |
|---|---|---|
| `thinkSupport` | 課題Bundle | 課題概要（目的・完了条件など）、出典、本人確認時刻、版 |
| `thinkConversations` | Chat | 質問・回答・引用・提案、送信時のSnapshot |
| `thinkProgress` | 課題Bundle | 到達状態、保留・再開の履歴 |
| `thinkAgentJobs`、`thinkAgentArtifact` | Bundle、成果物Think | Agentジョブと成果物 |
| `thinkExternal`、`thinkFileSearch` | Bundle | 外部書き出しとFile Searchストアとの対応 |
| `taskOrigin`、`taskContext`、`taskRelation`、`subtaskChat` | Bundle、Chat | 課題とChatの対応、親子関係 |
| `thoughtSupport` | Chat、Bundle | 旧AIの記録。読み取り互換のために残す |

### 3.3 パネルの役割（現行）

| パネル | 思考支援での役割 |
|---|---|
| Thinktank | 相談の入口。新規Chat、「相談を課題として開始」「相談に類似した課題を調査」 |
| Seeds | 課題の俯瞰。課題概要、資料、サブ課題一覧、到達状態、Agent、外部連携（補助機能は折りたたみ） |
| Develop | サブ課題の個別相談（専用Chat）、資料の閲覧・編集 |
| Harvest | 見直しと終了。**未接続**（計画の手順5） |

### 3.4 AIの動作を決めているもの

AIの動作は、次の4つの組み合わせで決まっている。外部の設定ファイルでは決まらない。

1. `server/services/AIProvider.ts` の `CONVERSATION_POLICY`（コード内の指示文）
2. 同じファイルの出力JSONスキーマ：`reply`、`citations`、`proposals`、`progressProposals`、`subtaskCandidates`、`pauseCandidates`
3. `server/services/ConversationService.ts` によるサーバー側の検証：引用の一致、提案できる項目の制限、件数の上限
4. 出力の各項目を表示し、本人確認を経て保存するクライアントUI

`.thinktank/thinktank.md` は、停止済みの旧ルート（`server/routes/chatRoutes.legacy.ts`）だけが読む。現在の思考支援AIには使われていない。`src/services/thoughtSupport.ts` の `SUPPORT_POLICY` も、旧UI（`SupportChat.legacy.tsx`）とそのテストからしか参照されていない。

### 3.5 有効化の状態

AIは環境変数 `THINK_SUPPORT_AI_ENABLED`、`THINK_SUPPORT_AI_PROVIDER`、`THINK_SUPPORT_AI_MODEL` がそろったときだけ有効になる。

- ローカル：`server/.env` に3つとも設定されている。
- Cloud Run（v2.1.3）：3つとも**設定されていない**ため、デプロイ版の思考支援AIは停止状態になる。`deploy.ps1` は `AI_PROVIDER` と `*_MODEL` だけを引き継ぎ、`THINK_SUPPORT_AI_*` は渡していない。

## 5. 未完了の作業

- **見直しと終了**：Harvestで目的・完了条件と残作業を照合し、本人の確認後に課題全体を完了にする。
- **通し検証**：「誕生日会を開催する」を例に、相談→課題化→サブ課題→個別解決→終了を、実BQ・実AIで確認する。
- **外部連携**：File Searchへの資料送信・同期、外部検索。
- **P7**：音声対話。
- **Electron／Local保存での思考支援メタデータ保存**：P2はBQモードのみ対応。
- **デプロイ版のAI有効化**：`deploy.ps1` で `THINK_SUPPORT_AI_*` を渡す。

## 6. 今後の方針（案）

### 6.1 最初に決めること：主軸

| 案 | 中身 | これまでの実装との関係 |
|---|---|---|
| A. 課題ライフサイクル | 現行計画どおり、Harvestでの見直し・終了を接続して一周させる | ほぼそのまま延長 |
| B. 追体験＋思考補完 | Thoughtの時系列ダイジェスト、聞いたときだけ外の視点を出すChat | ContextService・Provider境界・引用検証は流用。課題・サブ課題・到達状態は縮小または休止 |
| C. 併存 | 相談を入口に、課題化は任意の上位機能に置く。追体験は別の柱として追加 | UIが複雑になりやすく、基本メモ機能を損なわない配慮が要る |

### 6.2 主軸によらず残す土台

- Bundleを正本とし、AIは提案のみ行う。記録の変更は本人確認後に保存する。
- 資料の事実・AIの推論・本人の決定を区別する。引用は資料本文と照合する。
- AI-neutral：Providerを差し替えられ、AIが止まっても記録・編集が続けられる。
- 追加型のメタデータ保存（`schemaVersion` 付き）と、旧データの読み取り互換。

### 6.3 枠組みを変えやすくする準備（任意）

- `CONVERSATION_POLICY` を「モード」ごとの外部ファイルに分ける。ただし、出力スキーマ・サーバー検証・UIが対になっているため、指示文だけを変えても新しい出力項目は扱えない。モードは「指示文＋スキーマ＋検証＋表示」の組で定義する。
- 停止中の旧ルート・旧UI（`*.legacy.*`、`.thinktank/thinktank.md`、`SUPPORT_POLICY`）を、残すか削除するか決める。

### 6.4 文書の整理

- `docs/ThinkSupport/README.md` を、経緯の索引と「現行仕様の要約」に分ける。
- 概念の正本（旧 `docs/concept.md` 相当）を復活させるか、本書を後継にするかを決め、`CLAUDE.md` の参照を直す。
