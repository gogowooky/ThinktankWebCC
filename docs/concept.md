# Thinktank ── コンセプト / 機能・構造概要

> 本ドキュメントは「コンセプト（目的）」→「現状の機能・構造の整理」→「将来の方向性」の順でアプリ全体像をまとめたものです。
> 実装の細部ではなく、アプリが目指すものと現在地、そして向かう先を記述します。

---

## 1. コンセプト（目的）

### 最終的に解決したいこと

日々の自分の興味を「忘れずに持続・深化」させ、ときに「別方向へ目を向けるきっかけ」を得て興味範囲を広げること。
対象をより明確にすると ── **中高齢者の思考力・興味力の衰えを支援すること**。

### このアプリを他と差別化する“本質（軸）”

本質は次の掛け合わせにある:

> **⑤ グルーピング（Thought） × ⑥ 振り返り・追体験**

すなわち「関連するものを束ねた“思考のまとまり（Thought）”を、時間軸に沿って後から追体験できる」こと。
単なるメモの蓄積ではなく、**“自分が何を・どう考えてきたか”を後から辿れること**が核心。

そこに、興味拡大の“控えめ版”を添える:

> **＋ 思考の補完装置**

フルなセレンディピティ（全方位のレコメンド）までは求めない。
「自分の考えを補完するために、自分以外の意見を取り入れる“きっかけ”」── 主に AI との対話と、関連情報の提示 ── があればよい。

### 外せない土台

**② 記録の基本機能。** あくまで「信頼できる自分メモアプリ」であること。
上記の高度な機能はすべてこの土台の上に乗る付加価値であり、基本のメモ機能を曖昧にしない。

### 「実現したいこと」の全体像（①〜⑥）

1. ネット取得情報への再アクセスのきっかけを複数用意し、振り返りを容易にする
2. ネット情報などから得た自分の考えをメモとして記録する
3. テキスト以外のメディアで出力したファイル等への再アクセスのきっかけを複数用意し、振り返りを容易にする
4. 上記のインプット・アウトプットについて AI と語る
5. 関連付いたファイルや情報をグルーピングする
6. グループ内の情報の更新履歴を整備し、思考の内容を後から振り返れるようにする

## 2. 管理する情報（データの種類）

アプリが扱う情報は次の5タイプ（＋補助1）。すべて単一のデータ実体「Think」として保存し、種別タグ（`ContentType`）で区別する設計。

| # | 名称 | ContentType | 内容 |
|---|------|-------------|------|
| 1 | **Think** | `memo` | アプリ内で入力するテキストメモ。ファイルで管理。 |
| 2 | **Link** | `links` | 外部アプリで作った非テキストファイルの URI や Web URL を登録し、関連情報を追記して管理。 |
| 3 | **Chat** | `chat` | AI とアプリ内で対話した内容を保存して管理。 |
| 4 | **WebText** | `nettext` | 主にネット由来のテキスト情報。SNS・ブログ記事・Webメールの過去記事など**消滅の可能性がある**情報源を対象に、リンクだけでなく**コンテンツ本体までアプリ側に取り込んで保全**する（リンク切れ対策のアーカイブ）。 |
| 5 | **Thought** | `thought` | 関連するものをグループ化したもの。対象ファイルのリスト、またはフィルタ条件、さらにそのグループの履歴を保持する。 |
| （補助） | Table | `table` | 独自形式の表データ。上記を補助する位置づけ。 |

## 3. 現状の機能・構造概要（現在地）

### 3-1. データの考え方 ── 「すべては Think、Thought はその束」

- データ階層: **Vault（保管庫） > Thoughts > Thought > Think**
- 5タイプ（＋補助の Table）はすべて同一クラス（`TTThink`）で表現し、`ContentType` タグで区別。
  `memo` / `thought` / `table` / `links` / `chat` / `nettext`。
  → 構想の5タイプとほぼ 1:1 で対応済み。
- 1件 = 1ファイル（Markdown）。ID は作成時刻（`yyyy-MM-dd-hhmmss`）。タイトルは本文1行目から自動抽出。
- 各 Think は `Keywords`（検索用）と `RelatedIDs`（関連ID）を持つ。

### 3-2. 保存先（ストレージ）

実行形態に応じて保存先を自動切替（`StorageManager` が判定）:

- **Electron（デスクトップ）**: ローカルにファイル保存
- **ローカル開発**: ローカルFS
- **PWA / クラウド**: BigQuery（`thinktank.vault` テーブル）

メタデータのみ先読みし、本文は必要時に遅延ロードする（`IsMetaOnly`）。

### 3-3. Thought（グルーピング）── 現状すでに3方式に対応

Thought は本文に「束ね方」を記述する。3つの記法を混在・再帰可能:

- `* <ID>` : Think を直接 ID 指定でリスト化（**静的リスト**）
- `> …` : フィルタ条件（キーワード / 作成日 / 更新日）で**動的に収集**
- `>> …` : 全文検索条件で**動的に収集**

Thought の中に Thought を含められる（入れ子・合成が可能）。複数 Thought の連結や、チェックした項目からの Thought 生成にも対応。
→ 構想⑤「リスト、またはフィルタ方法」をほぼ満たしている。

### 3-4. AI 対話（Chat）

- 複数プロバイダ対応: **Anthropic Claude / OpenAI / Google Gemini**。
- SSE ストリーミングで逐次表示。
- 対話内容は `ContentType='chat'` の Think として保管庫に保存可能。
- 保存時に特定の Thought へ紐付け（その Thought のリストに追加）できる。
→ 構想④「AI と語る」と、対話の記録は実装済み。

### 3-5. 画面構成（4パネル）

- **Thinktank パネル（左端）**: 全 Think の一覧・検索・Thought 一覧・AI相談・設定。キーワード/日付フィルタ、表示項目・ソート設定、フィルタ履歴プルダウン。
- **Overview パネル（左から2番目）**: 特定の Thought を掘り下げる。Thought 内の Think 一覧、Thought 分析、AI相談、設定。
- **Workout パネル（中央）**: コンテンツの編集・作業領域。画面を再帰分割（BSPツリー）でき、1ペインを7種のビューで表示 ── テキストエディタ(Monaco) / Markdown / 表(DataGrid) / カード / グラフ / チャット。種別に応じて切替。
- **ReThink パネル（右端）**: AI との CLI 風対話・考察。
- **最下段ツールバー**: Status / Highlighter / KeyAction / Command / Translate / Reminder のモード。キーボードショートカット体系あり。

### 3-6. 検索・再アクセス・関連

- キーワード検索、作成日/更新日のレンジフィルタ、フィルタ履歴の保持。
- Embedding（ベクトル）基盤を保持（BigQuery 上のベクトルテーブル＋生成状態を管理する `TTEmbeddings`）。意味的な「関連」を扱うための土台。

### 3-7. 目的（①〜⑥）との合致度（現状評価）

| 目的 | 合致度 | コメント |
|------|:------:|----------|
| ② 記録の基本機能 | ◎ | 完成度が最も高い。アプリの最も強い部分。 |
| ⑤ グルーピング(Thought) | ○ | 3方式（リスト/フィルタ/全文検索）で実装済み。 |
| ④ AI と語る | ○ | 対話・保存・Thought 紐付けまで実装済み。 |
| ① ネット情報への再アクセス | △ | 検索/フィルタ/履歴で「探して戻る」は可能。「複数の能動的なきっかけ」はまだ弱い。 |
| ③ 非テキスト出力の再アクセス | △ | `links` 型はあるが、振り返りのきっかけは最小限。 |
| ⑥ 更新履歴・追体験 | ✕ | ほぼ未実装。あるのは検索フィルタ履歴と更新時刻のみ。コンテンツのバージョン履歴・変化のタイムラインはまだ無い（**最大のギャップ**）。 |
| ＋ 思考の補完（他者意見） | △ | AI 対話で部分的に可能。関連提示は基盤のみ。 |

**総括:**
「記録する・束ねる・AIと話す」までは土台ができている。
一方、本質と定めた**“時間軸での追体験（⑥）”**と、**“思考の補完装置”**はこれからの領域。アプリの個性はここを作り込むことで立ち上がる。

## 4. 将来の方向性

> ここは確定ではなく、議論の出発点としての方向性。順次精緻化する。

### 4-1. 第一の柱 ── 「思考のまとまり（Thought）を時間軸で追体験する」（⑤×⑥）

**ねらい:** Thought を「静的なグループ」から「時間とともに育つ思考のまとまり」へ。後から「自分がこの主題について何を・どう考えてきたか」を辿れるようにする。

**履歴モデル（2層構造）── 決定方針:**

- **Think 層（個別）**: すべての Think ファイルに、**更新履歴（いつ）と更新内容（何を変えたか）** を記録する。本文のバージョンを辿れる。
- **Thought 層（束）**: 配下ファイルの **ある期間の更新履歴・更新内容をまとめたダイジェスト** を Thought に記載する。あわせて **Thought の構成変化**（どの Think/Link/Chat/WebText がいつ束に加わった・外れたか）も残す。
  → Thought は「期間ごとの“思考のダイジェスト”」として育っていく。

**記録のタイミング ── 決定方針:**

- 保存のたびではなく、**節目（スナップショット）単位**で記録する。
- 節目は **1日の終わりに半自動**で作る。その日に更新があれば、日末にその日分の節目を生成する。
  → 履歴ノイズを抑え、対象（中高齢者）にとって追体験しやすい“1日単位の意味のある区切り”が残る。

**Thought ダイジェストの生成 ── 決定方針:**

- 配下ファイルの更新内容は **AI が要約してダイジェストを生成**する（機械的な羅列ではなく、文章としてのまとめ）。
  → 第三の柱「思考の補完装置」と接続する中核機能。AI が「この期間に考えが何へ向かったか」を言語化する。

**保存方式 ── 決定方針:**

- 履歴は Think 本体とは **別ファイル/別レコード**に持つ。
  → 本文を汚さず、履歴が増えても本体の取り回し（一覧・移動・編集）はスッキリ保つ。

**見せ方 ── 決定方針:**

- **時系列タイムライン**。「いつ・何が起きたか」を時間順に一覧し、そこから各時点の内容・差分へ辿れる。

**次に詰める論点（実装段階で）:**

- 日末「半自動」の具体（自動生成＋確認か、通知のみか）。
- Thought ダイジェストの対象期間の単位（日次／週次／任意区間）。
- 別レコードのデータ構造（既存の Vault/BigQuery 構造との整合）。

### 4-2. 第二の柱 ── 「再アクセスのきっかけ」を相関グラフで（①③）

**ねらい:** 記録を“探しに行く”だけでなく、関連で“引き寄せる”。忘れていた一件や、いま考えていることに近い過去メモへ、視覚的に再アクセスできるようにする。

**中心となる仕組み ── 相関グラフ（決定方針）:**

- Think 同士の **「近さ」を相関グラフで可視化**する。ノード＝Think/Link/WebText/Chat、エッジ＝近さ。近いものほど引き寄せ合って配置される。
- Thought 内の Think にも近さの濃淡があるため、束の“内部構造”が一目で分かる。
- **「近さ」の指標は切り替え可能**にし、選択の余地を残す:
  - **意味的な近さ**（Embedding ベクトルによる類似度）
  - **作業日時の近さ**（近い時期に触れていたもの）
  - **文書内リンクの有無**（`RelatedIDs` などの明示的なつながり）
  - …今後も指標を追加できる拡張余地を持たせる。
- 再浮上（「今の文脈に近い過去メモ」「しばらく育てていない束」など）も、**このグラフのページに集約して表示**する。
  → 通知で背中を押すのではなく、**ユーザーが開いたとき**にグラフ上で気づける“控えめ”な設計。対象（中高齢者）が迷わない。

**Link / 非テキスト出力への戻りやすさ ── 決定方針（③）:**

- 登録した外部ファイルの **格納場所を開ける**ようにし、**ワンクリックで開ける**状態にしておく。
- その Link について書いた Think や、含まれる Thought など **関連メモへの導線**を備える。

**次に詰める論点（実装段階で）:**

- 「近さ」指標のデフォルトと、複数指標の重ね合わせ可否。
- グラフからタイムライン（第一の柱）や本文へどう行き来するか。

### 4-3. 第三の柱 ── 「思考の補完装置」（④＋控えめな興味拡大）

**ねらい:** 自分の考えに、自分以外の視点を“きっかけ”として取り込む。全方位レコメンドではなく、いま考えていることに寄り添う補完。

**唯一の入口 ── 文脈付き Chat（決定方針）:**

- 補完機能は **「今の Thought / Think を渡した状態で AI と語る」文脈付き Chat に一本化**する。対話はそのまま Chat（`ContentType='chat'`）として履歴に残る。
- 別建ての“さりげない提示”は設けず、**ユーザーが聞いたときだけ**外の視点を出す。完全に受け身・ユーザー主導 ── これが「控えめさ」の設計。対象（中高齢者）にとって押し付けにならない。

**「自分以外の意見」の3つの出どこ（決定方針）:**

1. **AI 自身の見解・問い** ── 今の文脈を踏まえ、別視点・反論・問いを差し出す。
2. **過去の自分のメモ（AI が解釈して提示）** ── 過去のメモは断片的で「意見」としてまとまっていないため、AI がそれらを **解釈・束ねて“ひとつの視点”として** 提示する。第二の柱（相関グラフの意味的な近さ）で集めた関連メモが素材になる。
3. **ネット情報（WebText）** ── 取り込んだ記事や、そこから AI が見つける関連の外部視点。

**第一・第二の柱との接続:**

- 第一の柱の **Thought ダイジェスト（AI 要約）** は、この補完装置が「考えの変遷」を言語化したもの。
- 第二の柱の **相関グラフ（意味的な近さ）** は、AI が「関連する過去の自分」を拾う土台。
- → 3つの柱は **AI（思考の補完装置）を共通のエンジン**として一体で動く。

**次に詰める論点（実装段階で）:**

- 文脈として何をどこまで AI に渡すか（今の1件／Thought 全体／関連メモまで）。
- 過去メモの「解釈・束ね」の精度と、出典（どのメモ由来か）の見せ方。

### 4-4. 土台の入力経路 ── WebText（ネット情報）の取り込み（①の素材）

**位置づけ:** SNS・ブログ・Webメールなど**消滅しうる**情報源の本文を保全する、リンク切れ対策のアーカイブ（2章参照）。第一〜第三の柱すべての素材になる入力経路。

**取り込み手段 ── 決定方針:**

- **手動コピペを軸**にする。ブラウザ表示中の本文をコピーして貼り付けて保存。
  → ログインの内側（SNS/Webメール）でも認証の壁を受けず、何でも取り込める。最も確実。
- **出典 URL は自動補完を試みる**。Windows のリッチクリップボード（CF_HTML）の `SourceURL:` ヘッダから取得する。本アプリは Electron なので生のクリップボード HTML を読めば取得可能。
  - ただし 100% ではない（プレーンテキストのみのコピーや SNS アプリ内コピーでは取れないことがある）。
  - そのため URL は **自動補完＋手入力で編集できる欄**とし、「貼り忘れ」を実用上防ぐ。

**本文と一緒に保存する付随情報 ── 決定方針:**

- **出典 URL**
- **取得日時**（いつ時点の内容か）
- **自分のコメント**（なぜ保存したか・どこに興味を持ったか）
- **タイトル・著者等**のメタ情報
- **同じ URL を引用している他の Think 一覧**（URL を鍵にしたバックリンク索引）。
  - ただし **Google などの検索サイトの URL は「引用」として扱わない**（ノイズ除外）。

### 4-5. 貫く原則

- 「信頼できる自分メモアプリ」という土台（②）を常に最優先で保つ。高度な機能はその上に乗る付加価値であり、基本操作を複雑にしない。
- 対象（中高齢者）を意識し、操作の単純さと“迷わなさ”を重視する。

## 付録A ── このセッションで決めた方向性（要約）

3つの柱は **AI（思考の補完装置）を共通エンジン**として一体で動く。

- **第一の柱（⑤×⑥ 追体験）**: 2層履歴（Think＝個別の更新履歴／Thought＝AI要約の期間ダイジェスト＋構成変化）。節目は1日の終わりに半自動。履歴は本体と別レコード。見せ方は時系列タイムライン。
- **第二の柱（①③ 再アクセス）**: Think 間の「近さ」を相関グラフで可視化。近さ指標は切り替え可能（意味的／作業日時／文書内リンク＋拡張余地）。再浮上もグラフページに集約。Link は格納場所を開く＋ワンクリック起動＋関連メモ導線。
- **第三の柱（④ 思考の補完）**: 文脈付き Chat に一本化。聞いたときだけ、AI が①自身の見解・問い／②過去メモを解釈した視点／③ネット情報を差し出す。
- **WebText 取り込み（①の素材）**: 手動コピペを軸に＋出典 URL を CF_HTML の `SourceURL` から自動補完（編集可）。本文と一緒に 出典URL／取得日時／自分のコメント／タイトル・著者等／同URLを引用する他Think一覧（検索サイトURLは除外）を保存。

## 付録B ── まだ開いている論点（次のセッション以降）

- 履歴の「日末半自動」の具体（自動生成＋確認 or 通知のみ）、ダイジェストの対象期間（日次／週次／任意）。
- 相関グラフの「近さ」指標のデフォルトと、複数指標の重ね合わせ可否。
- 文脈として AI に渡す範囲（今の1件／Thought 全体／関連メモまで）と、過去メモ解釈時の出典の見せ方。
