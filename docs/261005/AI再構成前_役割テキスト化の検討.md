# AI再構成前：役割テキスト化とUI再配置の検討

作成日：2026-10-05。本書は今回示された方向を実装へつなぐための検討資料。現行仕様は [現状整理](AI再構成前_現状整理.md)、[固定UI一覧](AI再構成前_固定UI機能一覧.md)、[名称対応表](AI再構成前_名称・ファイル対応表.md) を参照する。

## 1. 今回示された方向

パネルの役割を編集可能なテキストとして表し、APIへの基本指示として渡して、各パネルのAIChatを構成する。後から役割を変更できるようにする。

アプリが提供する操作・表示・保存機能は、必要なものをアプリ内に実装する。初期の配置先は選ぶが、その配置とAIの役割が後から別々に変えられる構成を目指す。

先に話したループマネジメントの案や、現行４パネルの責務は、今回の整理を踏まえて大きく変更してよい。現行の課題ライフサイクルをそのまま完成させることを前提にしない。

## 2. 役割・操作能力・参照対象・UI配置を分ける

| 要素 | 定義する内容 | 変更の方法 |
| --- | --- | --- |
| パネルの役割 | 何を支援するか、何を重視するか、どんな問いをするか、どんな整理を返すか | 編集可能な基本指示テキスト |
| 共通のAI動作 | 事実・推論・本人の決定、出典、不明情報、提案と保存の区別等 | 共通の基本指示とサーバー側の検証 |
| 利用できる操作 | 概要更新、課題作成、進捗記録、成果物保存、資料取得等 | アプリに実装した操作と、その実行条件 |
| 参照対象 | どのChat／Bundle／子課題／資料を読むか | 対象ID、明示的な選択、Contextの組立 |
| UI配置 | ボタン、一覧、フォーム、候補確認をどこに見せるか | 共通UIの配置、表示設定、必要に応じてコード変更 |
| 保存形式 | 何を正本として保存し、どの履歴を残すか | schema、保存API、版管理、旧記録互換 |

役割文を変えると、既存の情報・操作範囲の中でAIの着眼点、問い、説明、提案の重点を変えられる。新しい担当・期限付きActionを保存する、新しいイベントを監視する等の能力は、対応するデータ・API・UIを実装して利用可能にする必要がある。

「UIをどのパネルに置くか」と「そのパネルのAIが何を考えるか」を別々に管理することで、役割変更に伴うUIの再実装を減らせる。

## 3. 現行コードで変更が必要になる箇所

| 現在の固定条件 | 今後検討する構成 |
| --- | --- |
| AIProviderの共通CONVERSATION_POLICYだけを送る | 共通基本指示と選択パネルの役割文を組み合わせてProviderへ渡す |
| 旧ROLE_POLICYは現行経路から未参照 | 役割文の編集・読込・有効化を現行経路に接続する |
| ConversationContext／生成要求に役割がない | 実際に適用したパネルID、役割設定の識別子・版を解決して記録する |
| Thinktankだけに課題化・類似課題UI | 機能の有無をパネル名の条件分岐から分離する |
| Thinktank以外に固定見直し質問 | 共通操作にするか、任意の質問候補として設定から読み込む |
| 子課題の担当・引継ぎがDiscuss固定 | 担当、表示先、関連Chatの起動規則を役割変更から独立して選べるようにする |
| ThinktankとPaneだけChat単独対話を許す | Chat単独／対象Bundle付きの利用方針を役割文とは別に定義する |
| Chat一覧は管理タイトルの担当とSeeds表示Bundleで絞る | 一覧範囲と対話対象のID対応を明確にし、役割変更時の一覧方針を選ぶ |
| 一部の操作は現在の共通出力schemaにない | 必要な操作についてschema、検証、確認UI、保存処理をそろえる |

特に、役割を記したMemoをそのままsourcesへ追加するだけでは基本指示として適用されない。現行CONVERSATION_POLICYは資料内の命令を参照データとして扱い、実行しない。役割設定はユーザーが設定として選んだテキストを、基本指示の経路に渡す必要がある。

## 4. APIに渡す基本指示の構成案

次の情報を区別して組み立てる。

1. 共通基本指示：出典、不明情報、提案と確定の区別、アプリ操作の契約。
2. パネル役割文：このパネルで何を支援するか、優先する観点と対話方法。
3. 利用可能な操作：アプリが実際に扱える提案の種類・入力項目。
4. 参照Context：対象ID、課題の現在地、資料、子課題、必要な会話履歴。
5. 今回の本人のメッセージ。

役割文の保存場所は、Vaultの設定用Think、専用設定ファイル、設定API等から選べる。現在の `.thinktank/thinktank.md` をそのまま使うと決まったわけではない。

| 設定に持たせる項目の案 | 目的 |
| --- | --- |
| パネルの識別子・表示名 | 保存IDと見せる名前を分離する |
| 役割テキスト | 日々の編集対象にする |
| 設定の版・更新日時 | 会話にどの指示を使ったか追えるようにする |
| 初期値／有効な設定 | 設定欠落時や変更取消時に動作を明確にする |
| 使える操作・UI表示 | 必要な機能を各パネルに配置する |
| 参照範囲の方針 | 役割文による無意識な対象拡張を避け、明示選択へつなぐ |

会話の記録には、適用した役割設定の版と、復元可能な指示文を残す案がある。役割変更は次の応答から適用し、過去の回答・決定を新しい役割で書き換えない。

## 5. これまでの役割を文章で表した初期値候補

以下は既存の責務を説明するための候補。新しいProgram Managerの役割を確定した文ではない。また、AIの実行権限や参照範囲の設定を兼ねるものではない。

| パネル | 役割テキスト候補 |
| --- | --- |
| Thinktank | 未整理の相談、気づき、資料を受け止め、本人が何に取り組みたいかを整理する。目的と対象を明らかにし、必要に応じて既存の課題との関係や課題として始める案を示す。重要な不明点を一つずつ確認する。 |
| Seeds | 対象のまとまりを俯瞰し、目的、完了条件、資料、関連課題、現在地、残る論点を整理する。部分の進捗と全体の目的の関係を示し、優先順位や依存関係を検討する。 |
| Discuss | 対象課題について、資料と本人の報告をもとに選択肢、仮説、根拠、不明点を整理する。次に行うことと確認する結果を具体化し、必要な資料・成果物・判断案を作る。 |
| Harvest | 実施結果を目的と期待した条件に照らして振り返る。達成した範囲、残課題、予想との違い、得られた知見を整理し、継続、変更、保留、終了と次回への引継ぎを検討する。 |

この４文を保存・API送信する機能は、今回の資料作成では実装していない。

## 6. アプリ側の機能と初期配置の検討

現在の機能を共通部品・サービスとして保ち、配置は次の観点で選ぶ。以下は候補であり、現状の移動を実施する指示ではない。

| 必要な機能 | 現在の配置 | 初期配置の候補 | 役割変更への対応 |
| --- | --- | --- | --- |
| 新規相談・対象の選択 | Thinktank中心 | Thinktank、共通Chat入口 | 任意パネルで使うか設定できる |
| 課題化・既存課題との対応 | Thinktank | 共通の会話付随操作 | パネル名だけで有無を決めない |
| 資料の収集・追加・除外 | Thinktank／Seeds | Thinktank／Seeds | 役割文と独立して資料を管理 |
| 構造・現在地の俯瞰 | Seeds分析 | Seeds | 全パネルから参照・更新を開ける |
| 基本情報・判断基準の編集 | Seeds課題概要 | Seeds／共通設定 | 共通の保存形式を使う |
| AI提案の採用・差分確認 | 共通AIChat | 共通AIChat | 役割が変わっても同じ操作契約 |
| Actionの採用・追跡 | nextAction／子課題のみ | Discuss＋Seeds一覧 | 担当者、期限、期待結果の新規実装が必要 |
| 実行結果・到達状態の記録 | Seeds／共通AIChat | Harvest＋共通対話 | 根拠の保存・本人確認を共通にする |
| 終結・残課題・知見 | 専用機能なし | Harvest | 正式な保存項目・操作を実装 |
| 要約・比較・成果物保存 | Seedsジョブ／Discuss編集 | 共通処理入口＋Discuss | ジョブ本体と表示先を分離 |
| 外部接続・同期設定 | Seeds詳細 | 設定領域 | 役割文から独立した接続機能 |
| パネル役割の編集・適用確認 | 専用機能なし | 各パネル設定または共通設定 | ４パネルの役割を後から変更する入口 |

いま必要な機能の置き場所を決める際は、固定UI一覧のIDを使って「保持」「移動」「共通化」「削除」「新規実装」を指定できる。名称・役割・配置・保存形式の変更を個別に選べる資料として本書群を使う。

## 7. 再構成ができたかを確認する観点

- 同じ資料・質問に対して、パネルの役割文を変更すると、役割に沿った問いと整理が変わる。
- APIに実際に適用した役割が渡り、会話記録からその設定を確認できる。
- 役割文を変えても、利用可能な操作・対象ID・採用前の提案が混同されない。
- 機能のUIを移しても、同じ課題・Chat・確認済み記録を引き継げる。
- 旧記録の名前や表示状態を、現行の決定・完了と誤認しない。

今回は現状の棚卸しと設計上の境界を整理した段階であり、基本指示の外部化やUIの追加・削除は次の作業になる。
